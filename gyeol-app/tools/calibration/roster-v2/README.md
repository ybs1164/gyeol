# 서로 다른 실력의 AI 1,000명

기준 AI 12종으로 1,456판을 두고, 실측 점수와 측정 오차를 고려해 기준점 8개를 선택했습니다. 이웃 기준점의 행동을 매 수 고유한 확률로 섞어 AI 1,000명을 만들었습니다. 같은 등급을 복제한 1,000명이 아니라 모두 다른 실수 확률·평균 탐색량·혼합 비율을 갖습니다.

추정 레이팅 범위는 **974~2207**, 간격은 약 **1.234 Elo**입니다. 내부에는 소수 둘째 자리까지 저장하고 화면에는 정수로 표시합니다. 기준 AI의 평균을 1500으로 맞췄으며, 균등 간격으로 생성한 1,000명의 평균은 1590.5입니다.

## 선택한 실력 기준점

| 기준 AI | 실수 확률 | MCTS 탐색 수 | 실측 레이팅 |
|---|---:|---:|---:|
| 첫걸음 | 99% | 0 | 974 |
| 아침 | 75% | 0 | 1136 |
| 이슬 | 35% | 0 | 1313 |
| 돌담 | 18% | 8 | 1483 |
| 솔숲 | 10% | 16 | 1622 |
| 너울 | 6% | 32 | 1753 |
| 노을 | 3% | 64 | 1954 |
| 한결 | 0% | 512 | 2207 |

풀잎(1024), 새싹(1209), 바람(1367), 벼리(1957)는 이웃과 실력 차이가 작아 별도 기준점에서 제외했습니다. 선택 간격은 최소 100 Elo 및 두 RD를 합성한 오차의 1.96배를 고려한 보수적인 기준입니다. 가장 강한 기준점은 유지합니다. 한결은 벼리와의 직접 대결에서 60판 중 57승을 기록했습니다.

MCTS 횟수 1~7을 새 단계로 사용하는 대신, 검증한 두 행동 사이를 확률적으로 섞습니다. 따라서 아주 적은 MCTS 때문에 중간 단계가 오히려 약해지는 문제를 줄일 수 있습니다. 실수하지 않을 때 정책만 쓰는 AI와 탐색을 쓰는 AI도 같은 방식으로 연결합니다.

## 점수의 의미

- 기준점 점수는 선후공 효과를 포함한 정규화 Bradley–Terry 모형으로 산출했습니다. 선공 678승, 후공 778승, 평균 23.5수이며 추정 선공 효과는 -36 Elo입니다.
- 개별 AI의 점수는 기준점 사이 **보간 추정치**입니다(`ratingSource: interpolated`). 1,000명의 독립적인 실측 레이팅은 아닙니다. 바로 옆 AI의 작은 차이까지 통계적으로 보장하지 않습니다.
- 개별 AI의 RD는 최소 80으로 두어 기준점의 RD를 그대로 복사하지 않습니다. AI 자신의 전적은 0판에서 시작하고 사람과의 실제 대국만 누적합니다.
- 기존 AI 10명의 이름·ID와 상대적 순서는 유지했습니다. 새 AI들을 사이에 배치하고, 가까운 실력 범위에서 최근 상대 5명을 가능한 한 피해서 매칭합니다.
- 모델과 추론 캐시는 서버에서 하나를 공유합니다. AI 1,000개의 모델 프로세스를 띄우지 않습니다.

## 파일과 재실행

- [1,000명 전체 목록 CSV](bots.csv): 실력 순번, ID, 이름, 추정 점수, 실수 확률, 평균 탐색량, 기준점과 혼합 비율. Windows Excel에서 열 수 있는 UTF-8 BOM 형식입니다.
- [기준점 대전 원자료](games.jsonl), [입력 기록](manifest.json).
- [서버 레이팅·행동 설정](../../../packages/server/src/bot-ratings.json).
- [별도 1,000판 원자료](../roster-check/games.jsonl), [구간별 검증 보고서](../roster-check/report.json).

프로젝트 루트에서 실행합니다.

```bash
npm run calibrate:bots -- --workers 7
npm run calibrate:bots -- --fit-only
npm run calibrate:bots -- --validate-roster --workers 7
npm test
npm run build
npm start
```

대전 원자료는 한 판마다 저장합니다. 같은 모델·설정으로 다시 실행하면 완료한 판을 건너뜁니다. 입력이 바뀌면 기존 폴더를 보관하고 새로 시작해야 합니다. 보정 결과는 서버 빌드 후 재시작해야 반영됩니다.

## 구현 확인

- 9개 테스트 파일의 43개 테스트, 타입 검사, 웹·서버 프로덕션 빌드를 통과했습니다.
- 빌드된 서버와 실제 ONNX 모델로 초급·중급·상급 계정의 매칭과 AI 착수를 확인했습니다. 974점 계정은 990점 AI, 1500점 계정은 1537점 AI, 2207점 계정은 2166점 AI와 매칭됐습니다.
- 세 경우 모두 기권 후 사람 점수만 움직이고 AI 점수는 유지됐습니다. 이 확인은 임시 서버·임시 저장소에서 실행하고 정리했습니다.
- 실제 로컬 서버를 1,000명 구성으로 다시 실행했습니다. 기존 사용자 데이터는 백업했고, 계정 ID·인증 토큰·생성일이 보존됐는지 확인했습니다.

## 실력 구간 검증 결과

2026-11-11에 기준점 보정 1,456판과 별도 검증 1,000판, 총 **2,456판**을 완료했습니다. 원자료의 판 번호·대진·시드에 누락·중복이 없고, AI 1,000명 전원이 정확히 선공 1판·후공 1판씩 참여했는지 확인했습니다.

기준점 보정과 별개인 난수 시드로, 추정 실력 순번이 200명 차이 나는 AI끼리 대전했습니다. 아래 네 구간에서 각각 200판을 비교했습니다. 나머지 200판은 양 끝 구간끼리 두어 전원이 선공·후공을 한 번씩 맡도록 설계했습니다.

| 비교한 순번 | 강한 쪽 승리 | 승률 | Wilson 95% 하한 |
|---|---:|---:|---:|
| 1~200 ↔ 201~400 | 164/200 | 82.0% | 76.1% |
| 201~400 ↔ 401~600 | 162/200 | 81.0% | 75.0% |
| 401~600 ↔ 601~800 | 164/200 | 82.0% | 76.1% |
| 601~800 ↔ 801~1000 | 149/200 | 74.5% | 68.0% |

네 구간 모두 사전에 정한 점수율 60% 이상, 95% 하한 50% 초과를 충족했습니다. 각 AI의 미세한 차이에 대한 증명과는 별도로, 실력 구간을 높였을 때 실제 대전 결과가 달라지는 것을 확인한 결과입니다.
