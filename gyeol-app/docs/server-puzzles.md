# 서버가 만드는 정답 하나짜리 퍼즐

2026-11-21부터 오늘의 퍼즐과 퍼즐 도전은 앱에 넣은 고정 은행 대신 **서버가 기보에서 발췌해 내려주는 은행**을 씁니다. 출제 기준은 "정답이 하나뿐인 국면"입니다.

2026-11-25부터는 여기에 **"상대가 방금 실수한 국면"**이라는 조건이 붙습니다. 모든 문제는 상대의 직전 수가 실수였던 판에서 시작하고, 푸는 사람은 그 실수를 응징하는 수를 찾습니다.

## 출제 기준: 상대의 직전 실수

| 판정 | 범위(퍼즐 국면의 남은 타일) | 실수의 조건 |
|---|---|---|
| 종국 계산(exact) | 1~9장 | 상대가 다른 수로 **이기거나 비길 수 있었는데**, 실제 수로 강제 패배가 됐다 |
| AI 탐색(ai) | 10~22장(첫 수 직후부터) | 상대의 AI 탐색 승률이 가장 좋은 다른 수보다 **35%p 이상** 떨어졌고, 실수 전에는 40% 이상이었다 |

- 첫 수와 패스는 실수로 보지 않습니다.
- 종국 계산의 실수는 상대가 지키던 결과를 보인 다른 수 하나를 다른 탐색 창(타일 차이 전체)으로 한 번 더 계산해 맞춰 봅니다.
- 은행의 각 문제에는 `mistake: { board, action, judge, before, after, best }`가 붙습니다. 실수 전 판, 상대가 둔 수, 상대 기준 평가(지킬 수 있던 결과 → 실제 결과), 그 결과를 지키던 다른 수입니다. 기준 코드는 `MISTAKE_CRITERIA`, `mistakeProblem`(`packages/core/src/unique-puzzle.ts`)입니다.
- 앱은 실수 전 판에서 상대의 실수 수를 먼저 두어 마지막 수로 표시하고, "방금 갈색의 수는 실수였습니다. 이길 수 있던 판에서 지는 수를 뒀습니다." 같은 한 줄을 보여 준 뒤 문제를 냅니다. 실수 기록이 없는 이전 은행도 그대로 풀 수 있습니다.
- 35%p는 앱의 수 평가에서 블런더(??)의 경계입니다. 오프닝 10수를 조사했을 때, 실제 기보 2,900수 중 101수가 한 번에 35점 이상 잃은 수였습니다.

## 정답이 하나라는 뜻

- 푸는 쪽 차례마다 이기는 수(종국 타일 차이 > 0)가 만드는 판이 **정확히 하나**입니다.
- 상대가 같은 값으로 막는 최선 응수가 여럿이면, 그 **모든** 응수 뒤에서도 이기는 수는 하나여야 합니다. 그래서 화면의 상대가 어느 최선 응수를 두더라도 정답 수순은 하나입니다.
- 서로 다른 행동이 같은 판을 만들면 한 가지 경우로 셉니다(화면에서 구별되지 않는 같은 수).
- 실제 대국에서 **이긴 쪽이 실제로 둔 수**가 그 유일한 정답이어야 발췌합니다.
- 한 수로 바로 끝나는 국면, 처음 선택지(서로 다른 결과 판)가 3개 미만인 국면은 뺍니다.
- 기준 코드: `packages/core/src/unique-puzzle.ts`. 앱과 서버가 같은 코드로 다시 확인합니다.

## 두 가지 문제

| 형식 | 목표 | 범위 | 판정 |
|---|---|---|---|
| 수순 문제 | 상대 최선 응수와 종국까지 두며 이기기. 차례마다 정답이 하나 | 남은 타일 1~6장 | 종국까지 계산 + 전수 탐색 재검사 |
| 한 수 문제(단 하나의 수) | 유리함(강제 승리)을 지키는 단 하나의 수 찾기. 둔 즉시 판정 | 남은 타일 4~9장 | 종국까지 계산. 6장 이하는 전수 탐색, 그 위는 다른 탐색 창으로 다시 계산 |
| 한 수 문제(AI 판정, `--ai-judge`) | 불리해지지 않는 단 하나의 수 찾기. 둔 즉시 판정 | 남은 타일 10~22장 | 모든 수를 MCTS 128회, 앞선 두 수와 50% 경계 ±20%p 안의 수는 512회로 다시 평가 |

한 수 문제의 조건:
- 둘 차례에 강제 승리가 있고, 승리를 지키는 수(서로 다른 결과 판)가 정확히 하나입니다. 나머지 수는 모두 무승부나 패배입니다.
- 실제로 둔 수가 정답일 필요는 없습니다(실전에서 놓친 수도 문제로 씁니다). 바로 끝나는 수, 선택지 3개 미만은 뺍니다.
- 난이도는 신경망이 정답에 준 확률(그럴듯한 오답이 많을수록 어려움), 선택지 수, 남은 장수로 추정합니다. 정답 판정에는 AI를 쓰지 않습니다.

AI 판정 한 수 문제(오프닝·중반)의 조건:
- 정답은 **둔 뒤에도 불리해지지 않는 수**, 곧 AI 탐색 승률 50% 이상인 수입니다. 이기던 판을 지키는 수도 정답입니다.
- 그런 수(서로 다른 결과 판)가 정확히 하나여야 퍼즐입니다. 탐색 오차로 갈리지 않도록 정답은 52.5% 이상, 나머지는 모두 47.5% 이하여야 합니다(`KEEP_PUZZLE_CRITERIA.notWorse`, `margin`).
- 앞의 "상대의 직전 실수" 조건을 함께 만족해야 합니다.

### 중반(남은 10장 이상) 문제는 얼마나 나오나

종국 계산은 남은 9장 근처가 한계입니다(10장은 국면당 수십 초, 절반 이상이 계산 한도 초과). 그보다 이른 국면은 AI 탐색으로 판정합니다(`--ai-judge`).

- 이전 기준(한 수만 승률 57.5% 이상, 나머지 50% 이하, 15%p 차이)으로는 보관 기보 45판의 남은 10~20장 국면 495개 중 문제가 **0개**였습니다. 깊이 탐색하면 둘째 수도 거의 같은 승률이었습니다(예: 90% 대 87%).
- 2026-11-25 측정: 실제 기보 오프닝 10수에서 상대가 35점 이상 잃은 직후 국면 41개를 모두 평가했습니다. 승률 50% 이상인 수가 하나뿐인 국면이 3개, 경계 여유(±2.5%p)까지 만족한 국면이 2개(약 5%)였습니다. 나머지는 대부분 불리해지지 않는 수가 6~20개였습니다. 실수 직후에는 응징하는 쪽이 크게 앞서서, 웬만한 수로는 50% 밑으로 떨어지지 않기 때문입니다.

### 종반 문제는 얼마나 줄었나

보관 기보 앞 81판에 새 기준을 적용하면 **수순 문제 0개, 한 수 문제(종국 계산) 4개(3판)**였습니다. AI 자가대국은 종반에 들어서기 전에 승패가 이미 갈려 있습니다. 그래서 정답이 하나뿐인 종반 국면이 있어도, 그 직전 상대의 수는 대부분 "이미 진 판에서 둔 수"라서 실수가 아닙니다(`opponent-already-lost`). 사람끼리 둔 온라인 대국은 보관 기보에 10판뿐이라 따로 재지 않았습니다.

## 만드는 곳과 검증

| 단계 | 위치 | 내용 |
|---|---|---|
| 원본 | 서버 | 패키지의 보관 기보(`puzzle-sources.json`, AI 대국 690판) + 운영 DB에서 정상 종국한 온라인 대국(읽기 전용) |
| 발췌 | `db-cli mine-puzzles` | 상대의 직전 수가 실수인 국면만 골라, 남은 타일 1~9장은 알파베타 정확 탐색(종국 값만, 휴리스틱 없음)으로, `--ai-judge`면 그보다 이른 국면은 AI 탐색으로 풀고 위 기준을 적용 |
| 독립 검사 | 같은 명령 | 저장한 모든 국면의 모든 수 값을 가지치기·캐시 없는 전수 탐색으로 다시 계산. 다르면 생성 중단, 계산 한도를 넘으면 그 문제는 제외 |
| 점수 | 같은 명령 | 복잡도 추정치 순으로 AI 기준점 8단계에 고르게 배치 |
| 배포 | `GET /api/puzzles` | 은행 파일을 다시 확인해 기준을 어긴 문제는 내보내지 않음. ETag·gzip·CORS(앱이 다른 출처에서 읽음) |
| 앱 | `apps/web/src/lib/puzzle-bank.ts` | 받은 은행을 다시 확인해 쓰고 기기에 저장. 서버에 닿지 않으면 마지막으로 받은 은행으로 출제 |

- 기준이 바뀌면 모든 대국을 다시 발췌합니다. 다 끝날 때까지는 이전 은행을 그대로 내려줍니다.
- `gyeol-puzzles.timer`가 매시 30분쯤 `gyeol-puzzles.service`를 실행합니다(Nice 19, CPUWeight 1, 게임 서버가 항상 먼저). 처리한 대국은 `/var/lib/gyeol/puzzles/mined.json`에 남아 다음 실행은 새로 끝난 대국만 봅니다. 한 번에 50분까지 일하고 다음 실행이 이어 갑니다.
- 서비스는 `--ai-dir`와 `--ai-judge`를 함께 넘겨 오프닝·중반 문제도 만듭니다. 개발 PC 표본에서 대국당 약 50초(4개 프로세스 동시 실행)였습니다. 기준이 바뀐 뒤 첫 전체 재발췌는 보관 기보 690판 기준으로 매시 실행 여러 번에 걸쳐 끝나며, 그동안은 이전 은행을 그대로 내려줍니다.
- 은행: `/var/lib/gyeol/puzzles/bank.json` (`PUZZLE_BANK`로 바꿀 수 있음). 은행이 아직 없으면 `/api/puzzles`는 503을 돌려주고 앱은 "다시 받기"를 보여 줍니다.
- 출력에는 닉네임·계정 ID·토큰이 없습니다. 온라인 대국 ID는 해시로만 남깁니다.

```bash
# 서버에서 상태 확인
sudo systemctl status gyeol-puzzles.service --no-pager
sudo journalctl -u gyeol-puzzles -n 40 --no-pager
curl -s http://127.0.0.1:8787/api/puzzles | head -c 300

# 개발 PC: 같은 생성기로 packages/server/data/puzzles/bank.json 생성 → npm run server 가 제공
npm run puzzles
```

## 기존 은행과의 차이

이전에 앱에 넣었던 실전 84문제 중 이 기준을 만족한 문제는 3개뿐이었습니다. 나머지는 이기는 수가 둘 이상이거나 중간에 정답 갈래가 생겼습니다. 기존 퍼즐 점수·전적·연속 기록은 그대로 두고, 풀던 문제가 새 은행에 없으면 다음 문제부터 새 은행에서 냅니다.

APK는 처음 한 번은 서버에서 은행을 받아야 퍼즐을 열 수 있습니다. 그 뒤로는 오프라인에서도 저장된 은행으로 풉니다.
