# 승률 검증과 속도 개선을 우선하는 수정 계획

2026-11-13. 이 문서는 이전 AI 복기 개선 계획의 우선순위를 대체한다. 이번 작업은 계획 수정이며 앱·모델 코드는 변경하지 않는다.

계획 실행 후의 실제 범위·30판 속도·128판 보정 파일럿은 [실행 결과](win-probability-execution.md)에 별도로 기록했다.

## 1. 목표와 이번 범위

먼저 **승률로 해석할 수 있는 평가와 빠른 전체 그래프**를 완성한다. 수 등급·묘수·해설 확장은 그다음이다. 그래프를 보기 위해 모든 후보의 등급 판정이 끝날 때까지 기다리는 현재 구조를 없앤다.

완료 결과는 다음 세 가지다.

1. ‘승률 70%’가 어떤 기준의 대국 결과를 예측하는지 정의하고 실제 결과로 검증한다.
2. 일반 분석은 실제 기보의 국면만 평가한다. 한 판에 수백 개 후보를 각각 정밀 탐색하지 않는다.
3. 보정 전 추정값, 보정한 승률, 최선 대응으로 증명한 승패를 데이터와 표시에서 구분한다.

기존 전체 수 목록·수순 비교·취소·캐시는 재사용한다. 등급은 별도 분석 결과가 준비되면 표시하고, 승률 계산을 막지 않는다.

## 2. 현재 문제를 수치로 확인

`tools/analysis/sample-game.json`과 `benchmark.json`을 다시 확인했다.

| 항목 | 현재 측정·구현 |
|---|---|
| 고정 실전 기보 | 23수, 실제 국면 24개 |
| 후보 비교 | 전체 444개 후보를 평가 |
| 시뮬레이션 | 후보별 완료 횟수 합계 18,216회. 신경망 호출 횟수와는 다름 |
| 전체 일반 분석 | 모델 준비 후 약 41.8초, 현재 PC 한 판 측정 |
| 확정 등급 | 6수, 나머지 17수는 확정 보류 |
| 그래프 점수 | 각 후보를 서로 다른 예산으로 탐색한 뒤 그중 최대값을 사용 |

속도 문제의 핵심은 그래프용 평가에 후보 전수 비교 비용까지 붙어 있다는 점이다. 워커·캐시는 화면 멈춤과 재분석 비용을 줄여 주지만 첫 분석의 총 계산량을 해결하지 않는다.

정확도 측면에서는 **잡음이 있는 후보 평가들의 최대값을 매 국면의 평가로 사용하는 방식**도 재검토해야 한다. 최댓값 선택은 낙관 편향을 만들 수 있으며, 후보 수·예산이 바뀌면 값의 의미도 달라진다. 이것이 현재 그래프 흔들림에 얼마나 영향을 주는지는 별도 측정한다.

115개 후반 국면의 후보 1,401개가 정확 탐색 정답과 일치한 것은 유효한 검증이다. 그러나 그 결과는 초·중반의 승률이 보정되었거나 전체 그래프가 정확하다는 근거가 아니다.

## 3. 승률 정의와 무승부 처리부터 바로잡기

### 현재 규칙에서는 이진 승률 보정을 먼저 검토한다

이번에 실전 원본 690판을 현재 규칙으로 재생한 결과:

- 불법 수 0, 미종료 기록 0.
- 690판 모두 타일 25장에서 종료.
- 무승부 0판.

기보 표본만으로 모든 무승부 가능성이 사라졌다고 단정하지 않는다. 다만 현재 규칙에는 다음 검증 가능한 성질이 있다.

- 타일 배치는 최대 5×5 범위이고, 패스가 아닌 합법 수마다 타일 하나가 추가된다.
- 타일이 있는 유효한 판이 25장 미만이면, 현재 경계 안의 빈자리 또는 확장 가능한 경계에 놓을 자리가 존재한다. 그 자리에 인접한 타일의 상대편은 해당 타일을 회전해 배치할 수 있다.
- 따라서 두 플레이어 모두 둘 수 없는 정상 조기 종국이 가능한지 위 성질로 확인한다. 패스로 차례가 넘어갈 수 있는 것과 두 쪽 모두 못 두는 것은 구별한다.
- 정상 종국이 항상 25장이라면 홀수 타일 합계이므로 무승부가 없다.

이 성질을 규칙에 대한 설명과 테스트로 고정한다. 임의의 빈 보드·손상된 초기판·다른 규칙 버전의 무승부 처리는 유지한다.

**현재 표준 규칙에서 무승부가 불가능함을 확인하면, 새 WDL 모델 학습을 선행 조건으로 두지 않는다.** 승·패 두 결과에 대한 보정부터 진행한다. 무승부가 가능한 규칙이 추가되면 해당 규칙에 한해 WDL 또는 별도 무승부 모델을 도입한다.

현재 신경망은 승패 결과를 목표로 단일 tanh value를 학습한다. 무승부가 없고 value가 올바른 기대 결과라면 `(v+1)/2`는 승리 확률과 일치한다. **문제는 변환식 자체보다 현재 v와 탐색 출력이 실제 결과 빈도에 맞는지 검증하지 않았다는 점**이다. 따라서 sigmoid로 모양만 바꾸거나 이름만 승률로 바꾸는 것으로 끝내지 않는다.

### 예측 대상

승률의 기준은 **양쪽이 동일한 버전·설정의 기준 AI로 계속 둘 때의 승리 가능성**으로 정한다. 모든 사람·모든 난이도에 대한 보편적인 승률로 설명하지 않는다.

- 기준 AI의 모델, 탐색 예산, 수 선택 방식, 난수 정책, 후반 정확 탐색 여부를 manifest에 고정한다.
- 무작위 진행을 사용한다면 강한 후보를 어떻게 표본 추출하는지와 seed를 기록한다. 실제 기보의 이후 수만 보고 모든 대안의 승률을 정답 처리하지 않는다.
- 결정적인 게임의 완전한 최선 대응 승패는 확률 그 자체와 구별한다. `provenOutcome`을 별도 저장한다. 증명 결과를 확률에 반영하려면 기준 AI가 증명된 승리 전략을 실제로 따르도록 평가 규약도 맞춘다.
- 시간패·기권의 승자를 보드의 승률 학습 정답으로 쓰지 않는다. 해당 보드는 따로 이어 두거나 보정 자료에서 제외한다.

## 4. 빠른 승률 그래프를 위한 계산 구조

```text
기보를 실제 국면 S0…Sn으로 재생
           │
           ├─ 각 실제 국면 신경망 평가
           │      └─ 이 경로 전용 보정기 → 빠른 전체 승률 그래프
           │
           └─ 국면마다 루트 MCTS 한 번, 공통 예산 적용
                  └─ 이 경로 전용 보정기 → 탐색을 반영한 전체 그래프

선택한 수의 등급·추천 수 요청
           └─ 실제 수와 유력 대안 비교, 별도 계산
```

두 경로 모두 보정 검증을 통과한 뒤에만 승률로 표시한다. 신경망 단독 값과 탐색 값의 보정기를 공용으로 사용하지 않는다. 검증 중에는 해당 경로를 형세 추정으로 명시한다.

### 실제 국면마다 루트 탐색 한 번

- 시작 실험 예산은 국면별 64회와 128회 두 가지다. 현재처럼 모든 합법 자식마다 12→48→96회 탐색하지 않는다.
- 24국면 기준 총 1,536회 또는 3,072회가 출발점이다. 현재 18,216회 대비 시뮬레이션 예산이 약 1/12~1/6이다. 이것을 그대로 실행 시간 개선 배수로 주장하지 않는다.
- 전체 국면에서 같은 읽기 규칙을 사용한다. 루트의 최다 방문 수 Q, 루트 방문 가중 평균 Q, 신경망 value를 고예산 기준과 실제 결과에 각각 대조해 선택한다. 현재 최다 방문 Q가 옳다고 가정하지 않고, 노이즈와 보정 오차를 비교한다.
- 보정기의 입력과 학습 자료는 최종 선택한 읽기 규칙·탐색 예산과 일치시킨다. 시간 한도로 중단된 탐색은 완료 예산을 기록하고 지원되지 않는 예산을 정상 보정 결과처럼 표시하지 않는다.
- 최대 후보 Q를 그래프 점수로 직접 사용하지 않는다. 루트의 방문 비율도 곧바로 승률로 해석하지 않는다.
- 그래프 계산에는 후보 전체 PV 추출·정렬·수 등급 계산을 수행하지 않는다. 실제 신경망 실행, 규칙 계산, 수순 추출 비용을 따로 계측한다.
- 인접 기보 국면의 트리 재사용은 별도 검증 후 적용한다. 루트 변경·관점 부호·재사용 방문 수와 신규 예산을 명시적으로 관리한다.

### 빠른 전체 미리보기

- 첫 국면 하나를 먼저 보여주는 것으로 속도 목표를 만족했다고 하지 않는다. **모든 실제 국면의 그래프가 보이는 시간**을 측정한다.
- 기존 모델을 먼저 사용한다. 24개 실제 국면은 신경망 실행 약 24회가 기본 경로다. 캐시 적중은 별도 집계한다.
- 현재 ONNX는 `[1,7,7]` 고정 입력이며, 내보내기도 batch 1로 되어 있다. 단순히 여러 판을 합쳐 전달한다고 배치 추론이 되는 구조가 아니다.
- 단일 추론 경로로 목표를 못 맞출 때 동적 batch 내보내기를 검토한다. 1/4/8 입력에서 수치 일치·지연·메모리를 비교하고, 배치가 빠르다는 측정 없이 도입하지 않는다.
- WebGPU·멀티 워커·양자화는 기본 해결책으로 채택하지 않는다. 호출 수를 먼저 줄이고, 남은 병목이 신경망 실행일 때 기기별 실측으로 선택한다.

### 후반과 수 등급은 필요한 곳에 계산 배정

- 마지막 실제 국면부터 정확 탐색을 시도하고 증명된 값을 캐시한다. 공유 가능한 정확 결과는 앞 국면에서도 재사용한다.
- 후반 계산에는 한 판 전체 시간 예산을 둔다. 국면마다 최대 350ms를 반복해서 그래프 완료 시간을 늘리지 않는다.
- 추천 수·응수 수순은 사용자가 해당 수를 선택했을 때 추출한다.
- 수별 등급의 상세 탐색은 승률 그래프가 나온 뒤 요청한 수 또는 주요 변화 구간부터 진행한다. 그래프의 앞뒤 승률 차이만으로 정확한 착수 손실을 판정하지 않는다.

## 5. 승률을 실제 결과로 검증하는 절차

1. **자료 감사:** 기존 690판의 모델·규칙·AI 강도·초기 배치·중복·정상 종료 여부를 정리한다. 섞인 AI 설정의 결과를 한 보정 대상으로 취급하지 않는다. 이 자료만으로 출시 검증을 끝내지 않는다.
2. **기준 자료 생성:** 고정 기준 AI로 새 완료 대국과 분기 국면의 후속 대국을 만든다. 불리·접전·유리, 초·중·후반, 실제 실수 직후를 포함한다. 목표 구간별 표본과 대국별 출처를 기록한다.
3. **자료 분리:** 보정 적합·설정 선택·최종 검사 대국을 미리 분리한다. 회전·대칭·동일 원본의 복제는 같은 쪽에 둔다. 공통 시작판처럼 반복되는 국면은 독립 대국의 승패 빈도 검사로 따로 보고하고, 미지 국면 일반화 검사는 겹치는 국면을 제외해 별도로 보고한다.
4. **가장 작은 보정기부터:** 단조 로지스틱 보정으로 시작하고 충분한 자료가 있으면 isotonic을 비교한다. 기본 입력은 고정한 평가값이며 남은 타일 수 같은 국면 단계 특징은 별도 검증 후 추가한다. 모델 용량을 늘리기 전에 오류의 구조를 확인한다.
5. **예측력과 확률 신뢰도를 함께 검사:** Brier score, log loss, reliability diagram, 구간별 표본 수·오차를 보고한다. ECE 하나나 승패 정답률 하나로 통과시키지 않는다. 항상 50%를 내는 모델이 보정되어 보이는 문제도 기준 모델 비교로 걸러낸다.
6. **보정으로 해결되지 않을 때만 모델 수정:** 고정 예산에서 국면 순위와 전술적 구분 자체가 나쁘면 보정만으로 해결할 수 없다. 기존 몸통·정책을 재사용한 가치 헤드 재학습 또는 고예산 분석을 학습한 작은 가치 모델을 검토한다. 신경망을 바꾸면 새 보정과 검사를 다시 수행한다.

수량은 임의로 ‘몇 천 판이면 충분’이라고 확정하지 않는다. 초기 1,000개 완료 대국/후속 실험을 기준으로 시간·분포를 측정하고, 승률 구간별 검증 오차가 원하는 범위에 들어올 때까지 추가한다. 동일 대국의 24개 국면을 독립 24표본으로 세어 불확실성을 줄여 보고하지 않는다.

### 그래프 흔들림 검사

- 각 점은 실제 i수 후 국면이며, 한 색의 관점으로 고정한다. 색 교환과 관점 부호를 검사한다.
- `같은 보드 + 다른 둘 차례`는 다른 상태다. 둘의 합을 억지로 100으로 만들지 않는다.
- 실제 국면이 바뀌어 생긴 전술 변화와 평가 오차를 분리한다. 동일 국면의 낮은/높은 예산 평가, 후반 정답, 실제 결과를 대조한다.
- 차례·국면 단계별 잔차를 보고한다. 인접 국면 평균이나 선 보간으로 홀짝 오차를 숨기지 않는다.
- 같은 국면을 방문 순서와 관계없이 재분석할 때 같은 버전·예산의 결과가 재현되는지 검사한다.

## 6. 속도·품질 합격 목표

다음은 새 구현에서 검증할 목표다. 아직 측정으로 달성한 수치가 아니다. PC와 대표 Android 기기·브라우저·전원 조건을 먼저 고정하고, 최소 30판에서 p50/p95를 측정한다.

| 항목 | 제안 목표 |
|---|---|
| 모델 준비 후 전체 빠른 그래프 | PC p95 1초, Android p95 2초 이내 |
| 모델 준비 후 전체 기본 탐색 그래프 | PC p95 5초, Android p95 10초 이내 |
| 최초 로딩 | 다운로드·ONNX 세션 생성·첫 추론을 분리 보고. 준비 후 수치에 숨기지 않음 |
| 캐시 재열기 | 저장된 한 판 그래프 표시 p95 0.3초 이내 |
| 계산 예산 | 모든 국면의 실제 추가 시뮬레이션·NN 실행·캐시 적중·정확 탐색 노드·완료 시간을 기록 |
| 확률 품질 | 최종 검사 자료에서 원래 `(v+1)/2`와 상수/국면 단계 기준보다 Brier·log loss 개선. 특정 구간의 악화도 보고 |
| 확률 구간 | 충분한 표본이 있는 주요 구간에서 예상 승률과 실제 승리 빈도 차이 5%p 이내를 목표. 대국 단위 신뢰구간과 표본 수 병기 |
| 구조 정확성 | 정상 종국, 패스, 기권·시간패, 색 변환, 점↔보드, 일관된 예산 검사를 통과 |
| 후반 증명 | 정확 완료로 표시한 결과와 독립 전수 검사 불일치 0 |

빠른 경로가 목표를 맞춰도 확률 검증이 실패하면 ‘보정된 승률’ 출시로 간주하지 않는다. 품질을 위해 더 계산해야 한다면 고예산 모드를 별도로 두고 기본 분석의 시간 예산을 유지한다.

## 7. 실행 순서와 판단 지점

| 순서 | 작업 | 다음 단계로 넘어가는 근거 |
|---|---|---|
| 1 | 25장 종료·무승부 가능성 검증, 승률 기준 정의, 병목 계측 | 규칙 설명·회귀 검사·현행 지연 분해표 |
| 2 | 승률 API 분리, 실제 국면당 루트 1회 구조, 전체 미리보기 | 동일 자료의 시간·NN 호출·예산·원시 평가 비교 |
| 3 | 새 기준 대국 수집, 보정 적합·설정 선택·최종 검사 분리 | 재현 가능한 manifest와 독립 검증 자료 |
| 4 | NN 전용·탐색 전용 보정기 검증, 모바일 측정 | 확률·성능 두 기준 통과한 전체 승률 그래프 |
| 5 | 통과한 승률에 수 등급을 다시 연결 | 등급 계산이 기본 그래프 지연을 늘리지 않음 |

우선 1~2단계의 개발은 약 2~3 작업일을 출발 가정으로 둔다. 3~4단계는 기준 대국 한 판의 측정 시간, 사용할 수 있는 계산 자원과 표본 충족 여부를 본 뒤 산정한다. 이번에는 학습·자료 수집 시간을 빼고 전체 완료 일정을 약속하지 않는다.

### 코드 변경 경계

- `packages/ai/src/win-probability.ts` 신규: 실제 국면의 평가·예산·보정·근거 상태만 담당.
- `packages/ai/src/analysis.ts`: 등급·후보 비교를 담당하고 위 평가 결과를 입력으로 사용. 그래프의 선행 조건에서 제외.
- `packages/ai/src/mcts.ts`: 그래프용 간단 반환 경로, 공통 루트 예산과 계측, 검증된 경우만 트리 재사용.
- `packages/ai/src/predictor.ts`: 실제 ONNX 실행 계측. 필요할 때만 별도 배치 실험.
- 복기 워커·저장소: 모델 세션의 순차 재사용, 그래프/등급 작업 큐 분리, 각 결과의 evaluator·budget·calibration 버전 기록.
- `Records.tsx`: 전체 승률 그래프 먼저 표시, 상세 수 분석은 별도 요청. 수 등급 작업 취소가 그래프 캐시를 지우지 않도록 유지.
- `tools/analysis/`: 실제 국면 벤치마크, 보정 자료 manifest, 확률·속도·모바일 보고서. 이전 후반 검증 자료는 별도 보존.

## 참고한 1차 자료

- [Leela Chess Zero: Win-Draw-Loss evaluation](https://lczero.org/blog/2020/04/wdl-head/) — 무승부가 있는 게임에서 기대 점수와 승리 확률을 구별하는 근거. 결에 WDL을 반드시 도입해야 한다는 근거로 사용하지 않는다.
- [Stockfish WDL model](https://github.com/official-stockfish/WDL_model) — 대국 결과로 평가값과 승·무·패 빈도의 관계를 적합하는 접근 참고. 체스용 계수는 결에 복사하지 않는다.
- [Guo 등, On Calibration of Modern Neural Networks](https://proceedings.mlr.press/v70/guo17a.html) — 예측 정확도와 확률 보정을 따로 검증해야 한다는 근거. 분류용 temperature scaling을 현재 회귀 출력에 그대로 적용하지 않는다.
