# 레이팅 보완 — 2026-11-12

기존 [점검 보고서](rating-audit-2026-11-12.md)의 다섯 문제를 보완했다. Glicko-2의 한 경기 계산은 유지하고, 점수 반영 자격·순위 자격·휴면 기간·저장 이력·표시 반올림을 수정했다.

## 점수와 배치 정책

- `ranked`, `wins`, `losses`는 완료한 랭크전의 실제 전적이다. 별도 `rated`는 배치에 인정되는 평가 횟수이며, 티어·배치 진행·퍼즐 첫 시작에 이 값을 사용한다.
- AI 또는 배치 5판을 완료한 상대와의 대국만 평가에 인정한다. 배치 중인 사람에게서는 승점과 배치 진행을 얻지 못한다. 상대가 인정된 기준점이면 신규 이용자도 정상적으로 승점과 배치 진행을 얻는다.
- 6수 전에 기권·시간패로 끝나면 승점과 배치 진행이 없다. 정상 종국은 수가 적다는 이유로 제한하지 않는다.
- 같은 사람 두 명은 선후공·시간 모드에 관계없이 24시간 안에 두 판까지만 제한 없이 평가한다. 세 번째부터 승점과 배치 진행을 제한한다. 제한 전 대국은 서버 저장 자료에서 확인하므로 서버 재시작으로 초기화되지 않는다. AI는 고정 기준점이므로 반복 상대 제한에서 제외한다.
- 위 제한 상황에서도 **패자의 점수는 내려간다.** 패배를 회피하려고 일찍 기권하거나 반복 대전을 이용할 수 없다. 제한된 승리에서는 RD도 낮추지 않는다.
- AI가 켜져 있으면 신규 계정 둘끼리는 바로 매칭하지 않고 각각 AI를 기다린다. 배치 완료 상대가 있으면 사람과 먼저 매칭할 수 있다. **AI를 끈 신규 서버에서는 배치 완료 상대가 없으면 신규 계정의 배치를 확정할 수 없다.** 기준점이 없는 계정끼리 점수를 만들어 순위에 진입시키지 않기 위한 정책이다.
- 대국 결과에는 플레이어별 제한 사유를 저장하고 결과 화면에 표시한다. 배치 도중에 상대의 자격이 바뀌어도 결과 당시의 사유가 유지된다.

## 순위 자격과 휴면

사람은 `rated >= 5`이고 현재 유효 RD가 150 이하여야 순위표에 포함한다. 배치 완료와 추정 점수의 안정성을 별도로 확인한다. AI는 기존처럼 실제 대국 전적이 있는 경우 표시한다.

휴면 RD는 마지막 평가 시각 `ratingAt`부터 경과한 하루마다 Glicko-2의 미참여 기간 공식을 적용하고 350에서 제한한다. 로그인·순위 조회 때는 원본을 바꾸지 않고 유효 RD를 계산하므로 반복 조회로 증가가 중복되지 않는다. 다음 실제 평가에서는 양쪽의 유효 RD를 사용하고, 갱신한 플레이어의 `ratingAt`을 대국 종료 시각으로 기록한다. 로그인 시각 `seenAt`은 휴면 계산에 쓰지 않는다.

## 신규 계정 생성

직접 연결 주소별로 1시간에 신규 계정 10개까지 허용한다. 기존 토큰으로의 재접속은 제한하지 않는다. 하나의 WebSocket에서 `hello`를 반복해 계정을 바꾸는 동작도 거부한다. 연결 주소와 생성 횟수는 메모리에만 보관하고 만료 후 삭제한다. 생성 한도는 서버의 `NEW_ACCOUNTS_PER_HOUR` 환경 변수 또는 `ServerOptions.accountLimit`으로 조정할 수 있다.

프록시가 전달한 주소 헤더는 무조건 신뢰하지 않는다. 역방향 프록시 뒤에서는 모든 사용자가 프록시 주소로 집계될 수 있으므로 공유 네트워크 규모에 맞춰 한도를 조정해야 한다. 이 생성 제한은 서버 재시작 시 초기화된다. 점수·배치 자격과 반복 대전 제한은 별도로 계속 적용된다.

## 저장과 기존 자료 이행

- 최근 300개 제한을 제거하고 이후 점수 변화를 모두 보존한다. 최고·최저는 별도 누적값으로 관리한다.
- 새 계정에는 생성 시각의 1500점 시작 기록을 남긴다. 기존 계정도 이력이 온전하다고 확인될 때만 시작 기록을 추가한다.
- 이미 300판 초과로 삭제된 이력은 복원한 것처럼 표시하지 않는다. `historyComplete: false`와 함께 화면을 ‘보관된 기록’, ‘기록된 최고/최저’로 표시한다. 기간 전 기준점이 없으면 주간 변화는 `–`다.
- 이력이 온전한 계정의 주간 변화는 실제 시작점 또는 기간 직전 기록으로 계산한다. 그래프도 임의의 1500점을 넣지 않고 실제 시간 간격을 사용한다.
- 최초 이행 전에 저장 파일을 `<원본 경로>.before-rating-v2.bak`으로 복사한다. 이미 있는 백업은 덮어쓰지 않는다. 계정 ID·토큰·기존 점수·전적은 유지하고, 기존 계정의 배치 인정 횟수는 기존 `ranked`에서 이어받는다. 과거 대국의 점수를 소급 취소하지 않는다.
- 표시 증감은 `round(after) - round(before)`로 계산해 표시된 전후 점수와 일치시킨다.
- 새 프로토콜 필드는 선택 사항으로 추가해 이전 서버의 기록도 화면에서 읽을 수 있게 했다. 서버 주소·계정 변경 시 이전 계정의 통계 캐시를 지우고, 대국 종료·재접속 시 열람 중인 이력을 다시 가져온다.

## 적용과 검증

`npm run build`로 웹·서버 산출물을 생성한 뒤 새 서버 프로세스를 실행하면 적용된다. 실행 중인 기존 서버에는 메모리에 올라간 이전 정책이 남으므로 재시작이 필요하다. 첫 실행에서 기존 자료가 자동 이행된다.

회귀 테스트는 신규 계정 10개의 0수 기권, 정상 완주로 우회하는 신규 계정 대전, 제한된 대국의 패자 손실, 반복 대진·색 교환·시간 모드 변경, 순위 자격, 휴면 후 조회와 실제 갱신, 300판 초과 이력, 반올림 일치, 기존 파일 백업·이행의 중복 방지, AI를 통한 신규 배치 경로를 포함한다.

검증 결과:

- `npm test`: 15개 파일, **82개 테스트 통과**.
- `npm run typecheck`, `npm run build`: 통과. 웹 및 서버 실행 파일을 생성했다.
- `npm run check:rating-ui`: 격리 Chrome의 390×844 화면에서 한국어·영어 통계 표시, 기록이 잘린 계정의 주간 변화 `–`, 최고·최저 보존, 가짜 상승선 없는 그래프, 초반 종료 제한 사유, 가로 넘침 없음을 확인했다. JavaScript 실행 오류는 없었다. [UI 검사 결과](../tools/rating-validation/ui-report.json), [모바일 화면](../tools/rating-validation/rating-mobile.png).
- 실제 로컬 저장 파일의 사본으로 **빌드된 서버**를 별도 실행했다. 기존 1005개 계정 자료를 읽고, 사용자 토큰·계정·점수의 유지와 백업 파일의 바이트 일치를 확인했다. 실제 원본 파일은 변경하지 않았다. [서버 검사 결과](../tools/rating-validation/server-report.json).

보완은 익명 계정의 즉시 점수 생성과 반복 몰아주기를 막기 위한 것이다. AI를 이길 수 있는 봇 사용, 계정 공유, 이미 배치를 마친 사람끼리의 조직적인 조작까지 식별하려면 계정 인증과 추가 부정행위 탐지가 필요하다. AI 1000명의 보간 정밀도와 퍼즐 난이도의 실측 보정은 이번 구현 범위에 포함하지 않았다.
