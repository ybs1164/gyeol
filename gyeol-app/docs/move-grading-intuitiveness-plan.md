# 수 평가 기준을 이해하기 쉽게 바꾸는 계획

작성일: 2026-11-16. 변경 전 소스를 확인해 작성한 계획이다. 이후 기능 구현과 자동·브라우저 검증을 완료했으며, 측정 결과와 검증 한계는 [구현·검증 결과](move-grading-implementation.md)에 기록했다.

목표는 사용자가 “왜 이 등급인가?”, “다른 수와 무엇이 다른가?”, “얼마나 믿어도 되는가?”를 선택한 수 화면에서 이해하는 것이다. 기존 7단계 등급과 색상을 유지하고, **등급은 최선 대비 손실, 특별한 성취는 보조 표시, 분석 신뢰도는 별도 상태**로 정리한다.

## 1. 현재 납득하기 어려운 부분

| 확인한 현재 동작 | 사용자에게 생기는 혼란 | 변경 방향 |
|---|---|---|
| `gradeMove()`는 손실 1·3·10·20·35를 경계로 6종을 반환한다. `good`은 손실 구간에 없다. | 범례는 7단계지만 `! 좋은 수`의 의미가 다른 등급과 다르다. | 7개 등급을 하나의 손실 순서로 연결한다. |
| `candidateGrade()`는 착수 전 신경망 값보다 좋아지는 후보가 하나면 그 수를 `good`으로 덮어쓴다. | 손실 0인 최선수가 `★` 대신 `!`가 될 수 있다. 평가 오차 수준의 작은 차이도 특수 판정에 영향을 준다. | 기본 등급을 덮어쓰는 조건을 제거하고, 의미 있는 유일한 수는 별도 표시한다. |
| 비교 기준인 착수 전 값은 신경망 단독 평가이고, 상세 분석의 후보 값에는 탐색이 적용된다. | 서로 다른 계산 경로의 차이를 수의 성취로 받아들이기 쉽다. | 같은 부모에서 얻은 후보 간 비교를 등급의 유일한 수치 근거로 삼는다. |
| `MoveReview`에는 현재 추천 수 버튼만 있다. | 아이콘은 보이지만 판정 이유와 실제 수·추천 수의 평가 차이를 알기 어렵다. | 선택한 수에 등급·한 문장 이유·비교값·근거 상태를 표시한다. |
| 확정 보류된 수는 `MoveGradeBadge`에서 등급을 다시 계산한다. `isIssue`와 그래프도 이 표시 등급을 쓴다. | 잠정 실수가 확정 실수처럼 목록과 그래프에서 강조될 수 있다. | 공통 판정 결과를 사용하고 잠정 상태를 목록·그래프에도 전달한다. |
| 안정성 검사에서 `best`와 `good`은 손실 경계 검사를 건너뛴다. | 경계에 걸린 좋은 등급의 확정 기준이 다른 등급보다 느슨하다. | 모든 추정 등급에 동일한 경계 보류 원칙을 적용한다. |

관련 근거: `packages/ai/src/grading.ts`, `packages/ai/src/analysis.ts`, `apps/web/src/components/MoveGradeBadge.tsx`, `MoveReview.tsx`, `AnalysisGraph.tsx`.

## 2. 기본 등급은 최선 대비 손실로 통일한다

착수자 관점으로 같은 부모 국면의 합법 후보를 비교한다. 기존 손실식 `L = max(0, (최선 후보 value − 실제 후보 value) × 50)`을 유지한다. 화면에서는 미보정 값을 **AI 평가점**으로 설명한다. 예를 들어 최선 72점·실제 60점이면 손실은 12점이다. 실제 승리 확률이 12%p 줄었다고 설명하지 않는다.

다음은 검증을 시작할 초기 경계안이다. 현재 주요 경계를 유지하면서 빠진 `good` 구간을 추가한다. 사용자가 느끼는 구분과 재분석 안정성을 확인한 뒤 확정한다.

| 기호 | 등급 | 추정 손실 L | 화면에 제시할 의미 |
|---|---|---|---|
| ★ | 최선수 | 0 ≤ L ≤ 1 | 현재 분석에서 가장 좋은 후보들과 차이가 거의 없습니다. |
| !! | 훌륭한 수 | 1 < L ≤ 3 | 최선에 매우 가까운 수입니다. |
| ! | 좋은 수 | 3 < L ≤ 5 | 최선보다 조금 낮지만 좋은 대안입니다. |
| ○ | 무난한 수 | 5 < L ≤ 10 | 더 좋은 대안이 있지만 평가 손실은 비교적 작습니다. |
| ?! | 부정확한 수 | 10 < L ≤ 20 | 더 좋은 대안을 놓쳐 평가가 낮아졌습니다. |
| ? | 실수 | 20 < L ≤ 35 | 최선 대비 평가 손실이 큽니다. |
| ?? | 큰 실수 | 35 < L ≤ 100 | 최선 대비 평가 손실이 매우 큽니다. |

- 모든 값은 착수자 기준으로 비교한다. 그래프의 표시 색을 바꿔도 수 등급은 바뀌지 않는다.
- 착수 전후 그래프의 높이 차이를 등급 계산에 사용하지 않는다. 현재 그래프와 후보 평가는 계산 경로가 다르므로, 상세 설명에는 해당 수의 후보 비교값을 쓴다.
- 화면에 반올림한 점수로 등급을 재계산하지 않는다. 경계 부근에서는 소수 첫째 자리의 손실을 함께 보여준다.
- `!!`를 “어려운 수를 발견했다”는 뜻으로 설명하지 않는다. 발견 난도와 희소성은 손실 등급과 분리한다.
- 모든 후보가 불리해도 최선의 저항은 `★`가 될 수 있다. 이때 “불리한 국면에서 최선의 대응”이라고 설명한다.

## 3. 종국까지 확인한 수는 결과로 설명한다

정확 탐색은 추정 점수의 크기보다 **최선 대응 시 승·무·패가 달라졌는지**로 판정한다. 현재 결과 중심 원칙을 유지하고 설명을 추가한다.

| 최선 후보의 결과 → 실제 수의 결과 | 기본 등급 | 이유 예시 |
|---|---|---|
| 승→승, 무→무, 패→패 | ★ | 최선 대응 시 가능한 결과를 유지합니다. |
| 승→무 | ? | 이길 수 있었지만 무승부가 됩니다. |
| 무→패 | ? | 비길 수 있었지만 패배하게 됩니다. |
| 승→패 | ?? | 이길 수 있었지만 패배하게 됩니다. |

- “승→패”는 착수자가 최선의 수를 골랐을 때와 실제 수를 골랐을 때를 비교한 표현이다.
- 최선 대응 결과가 같으면 최종 타일 차이가 작다는 이유만으로 등급을 낮추지 않는다. 승리를 유지하는 수는 여러 개일 수 있다.
- 모든 수가 패배면 “모든 후보가 최선 대응 시 패배합니다”라고 설명한다. `★`가 승리를 보장한다는 오해를 막는다.
- 정확 탐색 결과는 “승리 유지 / 무승부 기회 상실 / 승리 기회 상실”처럼 표시하고, 인위적인 50점·100점 손실을 주 설명으로 사용하지 않는다.
- 합법 수가 하나인 강제수와 강제 패스는 등급·평균 손실·실수 횟수 집계에서 제외한다.

## 4. 특별한 성취와 신뢰도를 별도로 표시한다

기본 등급은 그대로 두고 근거가 있을 때 보조 문구를 붙인다.

- **유일한 승리 수:** 전체 후보의 결과가 확인됐고 승리 후보가 실제 수 하나뿐인 경우.
- **유일한 방어:** 전체 후보의 결과가 확인됐고 패배를 피하는 후보가 실제 수 하나뿐인 경우.
- **승리 기회 상실 / 유일한 방어 놓침:** 기존 정확 탐색의 증명 조건을 유지한다.
- **유일한 유력 후보 · 추정:** 필요한 후보의 추가 탐색이 끝났고 2위와의 차이가 관측된 탐색 변동폭보다 충분히 큰 경우에만 검토한다. 구체적인 차이 경계는 검증 후 결정하며, 1차 필수 범위에는 넣지 않는다.

단순히 착수 전 신경망 값보다 조금 높다는 이유로 특별한 성취를 부여하지 않는다. 서로 다른 행동 번호가 같은 결과 보드를 만들면 “유일한 수”인지 결과 국면 기준으로도 확인한다. 동치 처리 기준을 정하기 전에는 추정 유일성 표시를 출시하지 않는다.

| 상태 | 사용자 표시 | 판정·집계 원칙 |
|---|---|---|
| 신경망 빠른 비교 또는 경계 불안정 | 잠정 · 추가 분석 시 바뀔 수 있음 | 잠정 아이콘을 유지하고 확정 실수 집계에서 제외한다. |
| 추가 탐색에서 후보 순위와 손실 구간이 안정됨 | 탐색 안정 · 추정 | 추정 판정으로 집계하되 종국 증명과 구별한다. |
| 전체 후보를 종국까지 확인 | 종국까지 확인 | 증명된 결과와 전술 표시를 사용한다. |

추정 구간은 실제 수와 최선권 후보의 변동을 확인한다. 손실 변동 범위가 등급 경계를 가로지르면 `★`와 `!`도 확정하지 않는다. 관측된 탐색 변동폭은 통계적 신뢰구간이 아니므로 확률적 보장처럼 설명하지 않는다. 빠른 비교에는 변동 측정이 없으므로 잠정 상태를 유지한다.

## 5. 선택한 수에 판정 이유를 복원한다

기본 카드에는 아래 네 가지를 표시한다.

1. 수 번호·등급·잠정 또는 분석 근거 상태.
2. 왜 그 등급인지 한 문장.
3. 실제 수와 추천 수의 비교. 추정은 평가점·손실, 증명은 승·무·패.
4. 실제 수와 추천 수를 전환해 상대 응수까지 보는 조작.

설명 예시이며 실제 기보의 측정값은 아니다.

```text
12수 · ? 실수 · 탐색 안정 · 추정
최선보다 AI 평가가 24점 낮은 수입니다.
추천 수 67점 / 실제 수 43점
[실제 수 보기] [추천 수 보기]

21수 · ★ 최선수 · 종국까지 확인
패배를 피할 수 있는 유일한 수를 찾았습니다.
실제 수: 무승부 / 다른 후보: 패배
```

판정 이유는 수치·확인된 결과·검증된 수순에서 정형 문장으로 만든다. 돌을 많이 뒤집었다는 사실만으로 좋은 수라 하거나, 확인하지 않은 “안전한 타일 확보”, “다음 공격 차단”을 이유로 생성하지 않는다. 목록과 보드에는 기존의 작은 아이콘을 쓰고, 상세 카드와 범례에 설명을 제공한다. 범례는 모바일 터치와 키보드로도 이름·기준을 확인할 수 있어야 한다.

판정 결과에는 `grade`, `provisionalGrade`, `reasonCode`, `lossPoints`, `status`, `badges`에 해당하는 정보를 담는 방식을 검토한다. 기존 `lossPp`의 외부 사용처를 확인한 뒤 이름 변경 또는 호환 필드를 정한다. UI에서 `candidateGrade()`를 다시 실행하는 현재 방식은 공통 결과를 읽는 방식으로 바꾼다.

현재 `GRADING_VERSION = 2`를 새 기준 버전으로 올린다. 저장 형태가 바뀌면 `ANALYSIS_VERSION = 4`도 갱신한다. 이전 원시 후보값을 옮겨 쓸 경우 모델·평가 경로·탐색 예산·변동 측정 등 새 판정에 필요한 근거가 모두 호환될 때만 재판정한다. 근거가 부족하면 해당 등급을 다시 분석한다. 현재 그래프 캐시는 등급과 독립이므로 그 분리를 유지한다.

## 7. 검증과 완료 조건

### 규칙과 일관성

- 경계 1·3·5·10·20·35의 직전·동일·직후를 검사한다. 손실이 커질수록 등급이 좋아지는 사례가 없어야 한다.
- 다른 후보보다 좋은 유일한 수도 손실 0이면 `★`를 유지하고, 특별한 성취만 추가한다.
- 색 반전, 관점 전환, 자동 분석·상세 분석·캐시 복원에서 같은 입력과 근거는 같은 판정을 내린다. 탐색 예산 차이로 판정이 달라지면 상태와 새 비교값으로 설명한다.
- 공동 최선, 전부 패배, 승리 유지, 승→무, 무→패, 승→패, 강제 패스, 종국 증명 예산 초과를 검사한다.
- 경계 불안정 시 좋은 등급도 보류한다. 잠정 실수는 확정 실수 집계에 들어가지 않는다.
- 같은 수의 카드·목록·보드 아이콘·그래프 설명과 필터가 서로 다른 판정을 표시하지 않아야 한다.

### 실제 기보 검증

- 기존 원본 기보에서 초·중·후반, 양쪽 색, 유리·불리한 국면을 포함한 고정 표본을 만든다. 선택된 승리 퍼즐만으로 전체 품질을 평가하지 않는다.
- 기보 단위로 기준 조정용과 최종 검사용을 분리한다. 같은 대국과 대칭·중복 국면을 양쪽에 섞지 않는다.
- 후반은 독립 전수 탐색과 일치해야 한다. 초·중반은 고예산 탐색을 비교 기준으로 쓰고 수학적 정답으로 부르지 않는다.
- 예산을 두 배로 늘렸을 때 `탐색 안정`으로 표시한 수의 등급 유지율 95% 이상을 목표로 한다. 보류율·분석 완료율·판정 가능한 수의 실제 건수를 함께 보고한다.
- 핵심 전술 실수의 오탐·누락과 새 등급 분포를 기존 기준과 비교한다. 기준을 느슨하게 만들어 실수 횟수만 줄인 것을 개선으로 평가하지 않는다.
- 같은 기보·모델·기기에서 빠른 등급 전체 표시 시간, 추가 탐색 시간, 캐시 재열기 시간을 비교한다. PC와 모바일 결과를 구분한다.
- 짧은 사용자 검토에서 설명을 읽은 사람이 등급 이유와 추천 수의 장점을 자기 말로 설명할 수 있는지 확인한다. 7단계의 인접 등급을 계속 혼동하면 다음 개편에서 단계 축소를 검토한다.

실행 시 관련 AI·캐시·번역 테스트, `npm run typecheck`, 웹 빌드, 실제 모바일 폭의 브라우저 검사를 수행한다. 이 문서 작성 단계에서는 앱 변경이나 성능·정확도 검증을 수행하지 않았다.

완료 조건은 모든 평가 대상 수가 **등급 또는 보류 상태, 판정 이유, 비교 근거**를 갖추고, 동일한 손실 순서를 지키며, 증명되지 않은 내용을 확정 결과로 표현하지 않는 것이다.

1인 개발 기준 예상은 규칙·공통 판정 1일, UI·캐시 1일, 기보 비교·조정 1~2일로 **3~4작업일**이다. 모델 학습과 실제 승률 보정은 이 일정에 포함하지 않는다. 먼저 기본 등급의 덮어쓰기를 제거하고 `!` 손실 구간과 설명 카드를 함께 구현한다.
