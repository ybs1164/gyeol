# 수 평가 재검토와 등급 제안

2026-11-16. 이번 변경은 등급 색·범례를 적용하고, 평가 문제를 재현해 개선 기준을 제안한다. 평가 엔진과 현재 7등급 경계는 변경하지 않았다. 아래 6등급은 검증 전 제안이다.

## 결론

가장 큰 문제는 등급 경계보다 **기본 복기가 상대 응수를 탐색하지 않은 값을 수의 품질로 보여주는 것**이다. 색은 선명하게 고치되, 평가 개선은 응수 탐색과 판정 신뢰도를 먼저 해결해야 한다. 일반 품질은 6단계로 단순화하고, 전술 성과는 독립 배지로 표현하는 방향을 권한다.

## 코드와 실제 기보에서 확인한 근거

- `packages/ai/src/analysis.ts`의 `analyzeGameGrades()` 기본 경로는 각 자식 보드에서 신경망을 한 번 실행하고 부호를 뒤집는다. `simulations: 0`이며, 상대가 반격하면 뒤집히는 수를 직접 읽지 않는다. `standard`는 여기서 끝난다. 현재 코드도 이를 잠정으로 표시하지만, 사용자는 선명한 `??`를 수에 대한 판단으로 받아들일 수 있다.
- `analyzePosition()`의 상세 경로는 후보마다 MCTS를 하고 일부 후보에 예산을 더 준다. 최선 후보와 실제 수가 탐색량에 따라 바뀐다. 얕은 값과 깊은 값을 섞어 최댓값을 취하므로, 아직 확인하지 않은 후보의 과대평가가 손실을 부풀릴 수도 있다.
- 기존 보고서의 상세 비교는 12국면이다. 초·중반 추정 8국면에서 기본 예산을 두 배로 했을 때 표시 등급 유지가 **4/8**이었다. 낮은 예산에서 안정 판정된 추정 수는 **0/8**이었다. 후반 종국 증명 4국면은 이 분모와 구분해야 한다.
- 이번에는 같은 모델로 그 12국면의 기본 빠른 평가를 다시 실행하고, 기존 고예산 탐색과 대조했다. 모델 해시 일치를 검사했고, 참조 보고서의 해시도 새 보고서에 남겼다. 초·중반 8국면의 빠른 평가 등급과 고예산 등급이 같은 것은 **1/8**, 손실 추정 차이의 절댓값 평균은 **12.69점**이었다. 빠른 평가가 20점 초과 손실을 붙였지만 고예산 탐색은 그렇지 않은 경우가 **2/8**이었다.
- 예: `game-8dbfebe414dc9fb4`의 4수는 빠른 평가에서 손실 **21.81점·실수**, 고예산 탐색에서 **0점·최선**이었다. 이는 평가 경로의 불일치를 재현한 사례이며, 고예산 탐색이 수학적 정답이라는 뜻은 아니다.
- 현재 `excellent`는 최선 대비 손실 1~3점에 `!!`를 붙인다. 이는 묘수의 증거가 아니다. `good`의 폭도 2점뿐이다. 상세 탐색에서 허용하는 후보별 변동 0.06은 후보 하나당 3평가점이고, 두 후보의 상대 손실 범위는 최대 ±6점까지 벌어질 수 있다. 이 정도 변동으로 1·3·5점을 구분하면 판정 보류가 많거나 등급이 흔들린다.
- 착수자 관점으로 부호를 뒤집는 비교 자체는 맞다. 문제를 단순한 선후공 부호 오류로 설명할 근거는 없다.
- 그래프는 별도의 루트 탐색·확률 보정 경로이고 등급은 후보 간 AI 점수 차이다. 그래프에서 떨어진 %와 등급 손실점이 일치한다고 설명하면 안 된다.

자료: [이번 대조 보고서](../tools/analysis/grading-audit/report.json), [기존 탐색량 비교](../tools/analysis/grading-v3/report.json). 기존의 선택된 작은 표본을 재사용했다. 신규 대국 일반화 정확도, 실수 검출 정밀도·재현율, 모바일 속도를 입증한 실험은 아니다. 고예산 기준에도 주요 실수 표본이 부족하다.

## 권장 등급: 일반 품질 6단계

착수자 관점에서 같은 평가 경로로 비교한 `L = max(0, bestValue - playedValue) × 50`을 사용한다. 단위는 실제 승률 %p가 아닌 AI 평가점이다. 아래 숫자는 기존 5·10·20·35점 경계를 대부분 유지하고 상위 두 세부 구간을 합친 출발안이다. 실전 의미에 맞게 검증한 최종값으로 취급하지 않는다.

| 등급 | 손실 L 초안 | 색 | 의미 |
|---|---:|---|---|
| 최선수 ★ | 0~2점 | 보라 | 분석 오차 범위 내 최선권 |
| 좋은 수 ! | 2점 초과~5점 | 초록 | 작은 손실의 좋은 대안 |
| 무난한 수 ○ | 5점 초과~10점 | 회색 | 개선할 수 있지만 결정적 손실은 작음 |
| 부정확한 수 ?! | 10점 초과~20점 | 노랑 | 의미 있는 대안을 놓침 |
| 실수 ? | 20점 초과~35점 | 주황 | 큰 형세 손실 |
| 큰 실수 ?? | 35점 초과 | 빨강 | 매우 큰 손실 |

이 안을 같은 초·중반 8국면의 저장된 탐색값에 적용하면 두 배 예산 등급 유지가 4/8에서 **5/8**로 바뀌지만, 저예산과 고예산의 일치는 기존과 새 안 모두 **5/8**이다. **등급 수를 줄이는 것만으로 평가 문제가 해결되지 않는다.** 표본에 맞춰 경계값을 더 조정하지 않았다.

`!! 훌륭한 수`는 단순 점수 구간에서 빼는 편이 낫다. 정말 특별한 수를 표현하고 싶다면 기본 등급 옆에 검증된 사실을 붙인다.

- 유일한 승리 수: 다른 결과 보드를 만드는 모든 후보의 결과까지 증명했을 때.
- 유일한 방어: 패배를 피하는 결과 보드가 하나뿐임을 증명했을 때.
- 승리 기회를 놓침 / 유일한 방어를 놓침: 대안과 실제 수의 결과가 증명됐을 때.
- 묘수: 유일수라는 사실만으로 부여하지 않는다. 뻔한 한 수와 어려운 발견을 구별하는 기준·사람 검증이 추가로 필요하다. 정책 확률이 작다는 사실만으로도 부족하다.

## 판정 우선순위

1. **강제수·강제 패스:** 등급과 실수 통계에서 제외한다.
2. **종국 결과 증명:** 승→승, 무→무는 결과 유지, 승→무·무→패는 실수, 승→패는 큰 실수다. 같은 승리의 최종 타일 차이를 이유로 감점하지 않는다. 모든 대안이 패배면 `패배 확정 · 결과 유지`를 앞세워, ★가 승리를 뜻하는 듯한 인상을 줄인다.
3. **응수 탐색을 마친 추정:** 최선 후보와 실제 수의 점수 차이로 일반 품질을 매긴다. 서로 다른 출처의 점수나 그래프 전후 차이를 섞지 않는다.
4. **응수 미확인 또는 불안정:** 빠른 참고값과 판정 보류를 명시하고, 실수 확정 통계와 전술 성과에서 제외한다. 단순 신경망 값에 `!!` 같은 강한 칭찬을 주지 않는다.

안정성은 등급과 별도 축으로 둔다. `종국 증명`, `탐색 확인·추정`, `잠정`을 구분한다. 두 탐색량의 값 차이만으로 얻은 범위는 통계적 신뢰구간이나 정확도 보장이 아니다.

## 평가 경로를 고치는 구현 순서

1. 모든 합법 후보의 결과 보드를 정규화해 중복 보드를 묶고, 기본 비교 예산을 맞춘다. 실제 수가 정책 상위 후보가 아니더라도 반드시 포함한다. 예산이 부족하더라도 상대의 즉시 승리 응수는 먼저 확인한다.
2. 빠른 후보 비교는 진행 중 참고값으로만 쓴다. 실제 수와 최선권 대안에 **상대 응수를 포함한 탐색**을 추가한 뒤 판정한다. 현재처럼 일반 분석을 신경망 1회 비교에서 완료 처리하지 않도록 분석 수명주기도 함께 고친다.
3. 실제 수와 최선권 후보가 같은 단계의 비교값을 쓰도록 하고, 판정에 영향을 줄 수 있는 미탐색 후보가 남으면 보류한다. `decideMove()`가 현재 최선에서 0.12 이내 후보만 안정성 검사에 포함하는 것도 검토해야 한다. 바깥 후보가 측정 없이 제외됐다고 뒤집힐 가능성이 사라지지는 않는다.
4. 예산을 늘릴 때 최선권 집합·손실 범위·등급이 함께 유지되는지 본다. 범위가 경계를 가로지르면 단정하지 않는다. 승패를 증명한 결과와 휴리스틱 추정은 항상 구분한다.
5. 그 뒤 6등급을 적용하고 등급 캐시 버전을 올린다. 순수 색 변경에는 캐시 무효화가 필요하지 않다. 그래프 캐시도 불필요하게 다시 계산하지 않는다.

## 다음 엔진 변경의 검증 조건

- 조정용 대국과 검증용 대국을 대칭·색반전·중복 국면 단위로 분리한다.
- 초·중·후반, 양쪽 색, 유리·불리, 강제 패스와 공동 최선, 실제 승→패·무→패 사례를 포함한다. 최선수 위주 표본만으로 실수 판정 성능을 주장하지 않는다.
- 후반은 저장된 독립 전수 탐색 결과와 비교하고, 초·중반은 더 높은 예산을 비교 기준으로 삼되 정답으로 부르지 않는다.
- 현재 방식 대비 실수 오탐·누락, 판정 가능 비율, 예산 두 배 등급 유지율, 최초 표시와 최종 판정 시간을 함께 측정한다. 판정 보류를 늘린 것을 정확도 개선으로 계산하지 않는다.
- `탐색 확인`으로 표시한 초·중반 수의 등급 유지율 95%를 개발 목표로 둘 수 있지만, 현재 자료로 달성했다고 주장할 수 없다. 모바일은 실제 기기에서 별도 확인한다.

## 이번에 적용한 시각 변경

현재 7등급은 보라·파랑·초록·회색·노랑·주황·빨강의 단색 면으로 구별한다. 밝은/어두운 테마에서 배지의 채도를 유지하고, 그래프에는 배경에 맞는 별도 잉크색을 쓴다. 등급 이름과 아이콘은 접힌 `등급 안내`에서 확인한다.

후속 화면 정리: 사용자 요청에 따라 물결·다이아몬드 표시를 제거했다. 추정 여부는 선택한 수 카드의 짧은 `추정` 문구로 구분한다. 화면은 선택한 수의 평가·추천, 승률 그래프, 수 목록 순서로 배치했고, 추천 버튼을 먼저 강조했다. 추정 점수 비교는 접힌 `세부 점수`로 옮기고 반복 설명·중복 배지·통계 설명은 줄였다. 내부 판정·통계·캐시 규칙은 유지했다. 후속 Chrome 검사에서도 배치 순서, 물결·다이아몬드 부재, 접힌 안내·세부 점수, 320px 다국어 표시와 기존 조작이 통과했다.

검증 결과: 타입 검사·웹/PWA·서버 빌드 통과, 화면·번역 검사 8개 통과. 실제 Chrome에서 밝은/어두운 테마의 7개 배지 배경 구분과 글자 대비를 검사했고 **최소 5.02:1, 최대 9.52:1**이었다. 390px 모바일·1440px 데스크톱, 320px의 한국어·영어·일본어·중국어 범례와 기준 표시가 가로 넘침 없이 통과했다. 기존 복기·캐시·수순·취소 검증도 통과했고 런타임 오류는 0건이었다.
