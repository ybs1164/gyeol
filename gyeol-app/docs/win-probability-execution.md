# 승률·속도·가시성 개선 실행 결과

2026-11-13. 수정 계획의 첫 구현과 보정 파일럿을 실행했다. **전체 그래프 계산을 수 등급 분석에서 분리했고, 검증을 끝낸 확률 보정의 배포는 아직 보류하고 있다.**

## 2026-11-15: 전체 수 자동 평가와 색상 아이콘

- 복기를 열면 저장된 결과를 먼저 불러오고, 부족한 그래프와 전체 수 등급을 자동 계산한다. ‘이 수 분석’을 누르는 단계는 없앴다. 수 목록·등급 범례·필터는 기본 화면에 펼쳐 두고 정밀 옵션과 통계만 접는다.
- 최선수는 보라 `★`, 훌륭한 수는 파랑 `!!`, 좋은 수는 초록 `!`, 무난한 수는 회색 `○`, 부정확한 수는 노랑 `?!`, 실수는 주황 `?`, 큰 실수는 빨강 `??`로 표시한다. 기호와 이름을 함께 사용하며 밝은/어두운 테마에서 구분한다. 강제수와 강제 패스는 별도 중립 표시를 사용한다.
- 목록·선택 수 상세·실수 그래프 표시에 같은 색을 사용한다. 방금 둔 타일 오른쪽 위에 같은 등급 아이콘을 붙인다. 중앙 정렬 뒤의 실제 배치 좌표에 표시하며, 착수 전 미리보기에서는 새 타일 미리보기에만 표시한다. 가상 추천 수순에는 실제 수의 등급을 붙이지 않는다.
- 그래프 전체 미리보기 → 전체 수의 빠른 등급 → 그래프 추가 탐색 순으로 표시한다. 전체 그래프 탐색이 끝날 때까지 등급을 숨겨 두지 않는다. 같은 워커와 ONNX 세션으로 모든 합법 후보의 자식 국면을 한 번씩 평가한다. 서로 다른 차례의 그래프 값 차이를 등급으로 바꾸지 않는다. 실제 착수도 빠뜨리지 않고 같은 부모·같은 깊이에서 대안과 비교한다.
- 빠른 신경망 비교는 `~` 잠정 등급으로 표시하며 확정된 판정으로 집계하지 않는다. 후반 전수 증명은 전체 수에 공유하는 180ms/75,000노드 예산을 사용한다. 승리 누락과 유일한 방어는 증명된 경우에만 확정한다. 정밀 분석을 선택하면 먼저 전체 잠정 등급을 표시한 뒤 추가 탐색을 진행한다.
- 그래프와 등급은 따로 저장한다. 등급 스키마만 v4로 변경했으며 기존 그래프 캐시는 재사용한다. 분석 중지 후에는 사용자가 재개하기 전까지 자동 재시작하지 않는다. 화면을 다시 열면 부분 결과를 복원하고 이어서 계산한다.
- 검증: 전체 125개 테스트 통과 후 표시 순서 검사를 2개 추가했고, 관련 27개 테스트·전체 타입 검사·웹/PWA 빌드·실제 Chrome 검사를 통과했다. 23수 기보의 단일 Chrome 측정은 전체 그래프 미리보기 3.074초, 전체 빠른 등급 표시 14.805초, 추가 그래프 탐색까지 완료 24.982초였다. 최초 계산을 즉시 완료하거나 이전 측정보다 일정 배수 빨라졌다고 주장하지 않는다. 캐시를 다시 열 때는 워커 생성 없이 그래프와 전체 등급이 표시되는 것을 확인했다.

### 등급 아이콘 정렬 보완

- 7개 등급과 강제수·대기 상태에 전용 SVG 아이콘을 사용한다. 글꼴의 기준선과 기호 폭에 영향을 받지 않도록 같은 24×24 좌표계를 사용한다.
- 배지는 타일 우측 상단 모서리에 고정하고, 아이콘은 정사각형 원형 배지의 가로·세로 중앙에 배치한다. 잠정 표시 `~`는 작은 보조 배지로 분리해 주 아이콘을 밀지 않는다.
- 착수 전 미리보기에도 타일 자체를 기준으로 같은 위치를 적용한다. 배지는 타일의 회전·뒤집기 요소 바깥에 있어 아이콘이 같이 회전하지 않는다.
- 브라우저에서 실제 배치·미리보기·잠정 배지·모바일·PC의 위치를 확인했다. 원형 배지의 가로·세로 크기와 SVG 중심의 오차가 0.6px 미만인지 검사했고, 7개 등급이 모두 전용 SVG로 표시되는 것을 확인했다. 타입 검사와 웹/PWA 빌드도 통과했다.

## 2026-11-14: 확정 승리의 수 표시

- 승리가 증명된 국면은 현재 값과 그래프의 선택 지점에 **‘N수 내 승리’**로 표시한다. 반대 색 관점에서는 ‘N수 내 패배’로 전환한다.
- 수는 양쪽의 착수와 강제 패스를 각각 1수로 센다. 승리 측은 승리를 유지하며 빨리 끝내고, 상대는 최대한 종국을 늦추는 전략을 기준으로 계산한다.
- 승패 증명을 먼저 완료하고 같은 시간·노드 예산의 남은 몫으로 수의 상한을 좁힌다. 거리 계산이 끝나지 않으면 타일 배치와 패스 규칙으로 보장되는 안전한 상한을 표시한다. 따라서 ‘N수 내’는 상한이며, 언제나 정확히 N수에 끝난다는 뜻은 아니다.
- 이미 끝난 종국은 기존 결과를 표시한다. 단순히 신경망 추정값이 100%에 가깝다는 이유로 확정 승리 수를 붙이지 않는다. 이전 그래프 캐시는 새 스키마로 구분해 다시 계산한다.
- 독립 전수 검사와의 거리 비교, 상대의 모든 지연 응수, 강제 패스, 색 반전, 예산 초과 시 안전한 상한, 표시·캐시 재열기를 검사했다. 전체 121개 테스트와 타입 검사·웹/PWA·서버 빌드, 실제 Chrome 검사를 통과했다.
- 고정 기보의 두 번 측정에서 추가 거리 계산 자체는 약 35~38ms였다. 전체 분석 시간의 일반적인 개선 배수나 p95로 해석하지 않는다. 기존 180ms/350ms의 종국 탐색 시간 예산은 유지한다.

## 화면에서 달라진 점

- 기본 화면은 보드, 이동 버튼, **승률 추정 그래프·현재 값·분석 상태**를 중심으로 구성한다.
- 수 목록, 일반/정밀 옵션, 필터와 통계는 ‘수 목록 · 상세 분석’에 접어 둔다.
- ‘이 수 분석’을 선택해야 해당 수의 등급·추천 수·응수를 계산한다. 평가 근거와 대안 전체 목록도 접어서 제공한다.
- 정상 종국은 ‘종국 결과’, 정확 탐색은 ‘최선 대응 결과’, 미보정 값은 ‘추정’과 ‘확률 보정 검증 중’으로 구분한다.
- 기존 기보 표기, 착수 전 미리보기, 좌표, 키보드 이동, 넓은 창의 보드/분석 패널 배치는 유지한다.

## 계산 경로

1. 기보의 실제 국면 전체에 신경망 평가를 적용해 전체 미리보기를 먼저 제공한다.
2. 마지막 국면부터 한 판 전체 시간 예산으로 후반 증명을 시도한다. 후보 전체를 나열하지 않고 필요한 루트 값만 구하며 정확한 결과를 재사용한다.
3. 나머지 실제 국면마다 기본 64회, 정밀 128회 MCTS를 한 번 수행한다. 그래프 경로에서는 후보별 PV 생성과 수 등급 계산을 하지 않는다.
4. 루트 방문 가중 평균값을 사용한다. 이 방식은 파일럿의 설정 선택 대국에서 정했으며 최종 검사 결과로 다시 선택하지 않았다.
5. 선택한 수의 상세 분석은 별도 작업으로 실행한다. 그래프와 상세 수 분석은 같은 ONNX 세션을 재사용하지만 캐시와 완료 상태는 분리한다.

그래프 캐시는 모델·규칙·읽기 규칙·예산·보정 버전·시작판·실제 수순으로 구분한다. 수 등급 버전만 변경되어도 그래프를 다시 계산하는 구조는 제거했다. 취소·화면 이탈 시 워커를 종료하고 부분 결과부터 재개한다.

## 속도 측정

서로 다른 실제 기보 30판, 준비된 Node/WASM 모델 세션으로 측정했다. **매 판 추론 캐시는 비웠다.** Android 실기기와 네트워크 다운로드 시간은 포함하지 않는다.

| 항목 | 중앙값 | p95 |
|---|---:|---:|
| 전체 그래프 미리보기 | 0.095초 | 0.123초 |
| 기본 탐색 완료 | 4.091초 | 4.578초 |

모델 세션 생성은 별도로 약 0.418초였다. 초기 기보 예시는 시뮬레이션 18,216회에서 1,152회로 줄었고, 실제 ONNX 실행 925회·캐시 적중 250회였다. 시뮬레이션 횟수와 ONNX 실행 횟수를 동일한 수치로 보고하지 않는다.

이전 41.8초는 고정 기보 **한 판**의 측정이었다. 새 30판 p95와 같은 모집단의 전후 통계라고 주장하지 않는다. PC의 준비된 엔진 경로에서는 제안한 5초 목표 안에 들어왔으며, 브라우저 전체 경로의 p95와 Android 10초 목표는 별도 측정이 필요하다.

## 승률 보정 파일럿

기존의 서로 다른 AI 실험 기보를 한꺼번에 보정 정답으로 사용하지 않고, **고정한 모델과 AI 정책으로 새 대국 128판**을 생성했다.

- 기준 AI: 모델 `900c6f08b6ce0aba…`, 64회 MCTS. 수 선택 온도와 seed를 고정하고, 남은 3장 이하에서는 정확 탐색을 사용한다.
- 대국 단위 분할: 적합 78판, 설정 선택 25판, 최종 검사 25판.
- 회귀 값의 단조 확률 보정, Brier score·log loss·구간별 실제 빈도, 대국 단위 bootstrap 신뢰구간을 계산했다.
- 적합·설정 선택 대국에 없던 정규 보드만 따로 검사하는 결과도 보관했다. 공통 초반 국면을 미지 국면의 성능으로 오인하지 않는다.

최종 검사 25판의 Brier score는 다음과 같다. 낮을수록 좋다.

| 평가 입력 | 보정 전 | 보정 후 |
|---|---:|---:|
| 신경망 단독 value | 0.27417 | 0.22498 |
| 최다 방문 수 Q | 0.21661 | 0.21387 |
| 루트 방문 평균 | 0.21492 | 0.21442 |

루트 방문 평균의 보정 후 Brier 95% bootstrap 구간은 약 0.171~0.256으로 넓다. 현재 표본만으로 일반적인 승률 신뢰도나 구간별 5%p 목표를 달성했다고 판단하지 않는다. 세 후보 모두 `accepted: false`로 보관했고 **앱의 보정기 목록에는 아직 연결하지 않았다.** 현재 화면의 비종국 값은 미보정 AI 추정값이다.

## 검사와 수치 오류 수정

전체 106개 테스트와 타입 검사·웹/PWA·서버 빌드를 통과했다. 실제 Chrome에서 간결한 기본 화면, 그래프와 수 분석의 분리, 모델 세션 재사용, 캐시 재열기, 취소·재개, 수순 좌표, 모바일·넓은 창을 검사했다.

Chrome 한 번의 검사에서는 새 워커·세션 준비를 포함해 전체 미리보기 약 0.452초, 탐색 완료 약 3.646초, 취소 반응 약 11ms였다. 모델 파일은 이전 검사에서 캐시된 조건이며, 이 한 판을 브라우저 p95나 최초 다운로드 시간으로 표현하지 않는다.

대국 수집 중 WASM tanh가 `−1.000000119…`를 반환하는 사례를 재현했다. `1e−6` 이내의 끝점 오차만 ±1로 보정하고, NaN·무한대·큰 범위 이탈은 계속 거부하도록 수정했다. 해당 사례와 범위 밖 오류에 대한 회귀 테스트도 추가했다.
