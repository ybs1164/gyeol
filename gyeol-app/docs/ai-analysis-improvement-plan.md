# 결 AI 복기 분석 개선 계획

작성일: 2026-11-12. 현재 `gyeol-app` 소스를 확인해 작성한 설계안이다. 구현 완료나 성능 측정 결과를 의미하지 않는다.

후속 구현의 실제 완료 범위·검사 결과·남은 과제는 [구현 및 검증 보고서](ai-analysis-implementation.md)에 기록했다. 아래 경계값과 목표는 당시 설계안으로 보존한다.

2026-11-13: 이후 우선순위는 [승률 검증·속도 개선 수정 계획](win-probability-speed-plan.md)으로 대체한다. 승률과 전체 그래프 완료 시간을 먼저 해결하고 수 등급의 확장은 후순위로 둔다.

## 1. 목표와 우선순위

우선순위는 **평가의 의미·관점 정리 → 탐색 기반 분석 → 그래프와 전체 착수 등급 → 수치 보정과 검증**이다. 그래프와 수 등급은 동일한 분석 결과를 사용한다. 그래프를 보기 좋게 만드는 것과 분석 정확도가 높아지는 것은 별도 지표로 확인한다.

완성된 복기는 다음 질문에 답해야 한다.

- 지금 누구에게 유리하고, 분석은 얼마나 안정적인가?
- 이 수는 가능한 대안보다 얼마나 손해인가?
- 더 나은 수와 상대의 최선 응수는 무엇인가?
- 승리 기회나 유일한 방어를 어디서 놓쳤는가?

## 3. ‘승률’의 의미부터 정리

현재 추론기는 단일 value를 반환하고 복기는 `(value + 1) / 2`를 승률처럼 표시한다. 학습 코드는 종국 결과를 목표로 사용한다. 이 값이 기대 결과 `P(승) − P(패)`를 근사한다면 변환값은 **P(승) + 0.5 × P(무)**에 해당한다. 단일 value만으로 승리 확률과 무승부 확률을 분리할 수 없다. 배포 모델의 학습·내보내기 경로도 함께 확인한다.

- 1차 배포: 그래프 제목은 **AI 형세 평가**, 설명은 ‘높을수록 해당 색에 유리’로 한다. 실제 승률로 오인되는 소수점 정밀도는 피한다.
- 후속 배포: 승·무·패를 따로 출력하는 WDL 헤드와 검증용 보정기를 준비한다. 검증을 통과하면 **예상 승률** 및 무승부 가능성을 표시한다.
- 보정 기준은 ‘고정한 분석 엔진과 상대 정책으로 이어 뒀을 때의 결과’로 명시한다. 사람의 실력이나 서로 다른 AI를 상대로 한 승률과 같다고 주장하지 않는다.
- 봇 Elo 보정은 봇의 상대적 실력 측정이다. 국면 승률의 확률 보정을 대신하지 않는다.
- 종국의 `result()`는 무승부를 `1e-4`로 표현한다. 분석 경계에서 반드시 승 1 / 무 0 / 패 −1로 변환한다. 기존 MCTS도 이 작은 무승부 편향을 함께 점검한다.

## 4. 공통 분석 엔진

### 4.1 평가 관점과 계산식

`S_i`는 i수가 끝난 국면이며 `S_0`는 시작 국면이다. 그래프는 항상 +1 색 기준으로 저장하고, 스킨에 맞는 색 이름으로 표시한다. 차례가 바뀔 때마다 선의 의미가 바뀌면 안 된다.

```text
V_i = S_i의 둘 차례 기준 탐색 평가, 범위 −1..1
G_i = (1 + player_i × V_i) / 2     // 그래프의 +1 색 기준 평가

Q_i(a) = S_i에서 a를 두고 상대가 응수하는 가치를, 착수자 기준으로 환산
E_i(a) = (Q_i(a) + 1) / 2
loss_i = 100 × max(0, E_i(best) − E_i(played))  // 단위: %p
```

모든 Q는 부호·평가 방식·보정 버전·비교 예산을 맞춘다. 기존 신경망 출력은 −1..1이라 마지막 1/2 변환이 필요하다. 추후 실제 승률을 사용할 때도 그 차이의 단위는 %p다.

`best`는 충분히 검토한 후보 중 추천 수다. 탐색으로 추정한 최선과 전수 탐색으로 증명한 최선을 구별한다. 표본이 적은 후보의 높은 Q 하나만으로 최선을 확정하지 않는다.

그래프의 `G_(i+1) − G_i`와 `loss_i`는 서로 다른 탐색의 영향을 받으므로 반드시 일치하지는 않는다. 큰 불일치는 재분석 대상으로 삼고, 억지로 선을 보정하거나 손실을 누적해 그래프를 만들지 않는다.

### 4.2 초·중반: 후보 탐색과 실제 착수 검증

1. 모든 합법 수의 즉시 종국 여부와 1차 신경망 평가를 구한다.
2. 부모 국면 MCTS로 유망 후보와 상대의 강한 응수를 찾는다. 복기에는 대국 난이도에 따른 고의 실수나 탐색 노이즈를 적용하지 않는다.
3. 실제 둔 수는 정책 확률이나 방문 수가 작아도 반드시 별도 탐색한다.
4. 상위 후보 3개와 실제 착수, 전술적으로 위험한 후보를 같은 자식 탐색 조건에서 비교한다. 후보별 최소 예산을 확보한 뒤 애매한 후보에 추가 배정한다.
5. 후보 순위가 바뀌거나 등급 경계에 가까우면 예산을 늘린다. 제외한 후보가 아직 충분히 검토되지 않았다면 ‘추정’ 상태를 유지하고 후보 범위를 넓힌다.
6. 실제 착수와 추천 수 각각의 상대 응수 및 후속 3~5수를 저장한다. 수순은 실제로 탐색·검증한 합법 수만 표시한다.

시작 실험값은 부모 탐색 128회, 주요 자식별 128회, 정밀 재검사 512회다. 이는 성능 보장이 아닌 벤치마크 출발점이다. 전체 후보 수에 따라 비용이 늘어나므로 PC·모바일 측정 후 조정한다. 실행하지 않은 탐색 횟수를 완료한 것처럼 기록하지 않는다.

MCTS의 방문 횟수는 독립적인 승패 실험 수가 아니다. 방문 수만으로 통계적 95% 신뢰구간을 만들지 않는다. 예산 2배 증가 시 Q와 추천 후보의 변화, 후보 간 격차, 실제 착수의 탐색량을 사용해 **평가 안정성**을 표시한다. 예산을 늘려도 남는 모델 오차는 따로 검증한다.

### 4.3 후반: 기존 정확 탐색기 재사용

`packages/core/src/endgame.ts`의 `ExactEndgame`은 실제 종국의 타일 차이를 반환하고 계산 한도 초과 시 실패한다. 퍼즐 생성기는 이를 사용하며 별도 전수 검사기도 존재한다.

- 남은 배치 타일이 5개 이하인 국면부터 시도하되, 장수만으로 완료를 보장하지 않는다. 패스가 있어 남은 배치 수와 실제 ply 수는 다를 수 있다.
- 워커에서 실행하고 노드·시간·메모리 한도를 둔다. 현재 동기 탐색기는 청크 실행 또는 취소 확인이 가능하도록 조정한다.
- 완료된 후보에만 ‘종국까지 확인’ 표시를 붙인다. 중단된 후보는 추정 탐색으로 돌아가며 전체 국면을 증명 완료로 표시하지 않는다.
- 승 > 무 > 패를 1차 목표로 삼는다. 모든 후보가 같은 승패를 유지하면 모두 결과상 최선으로 인정하고, 최종 타일 차이는 별도 보조 지표로 보여준다.
- 정확 탐색의 타일 차이는 부호로 승·무·패를 판정한 뒤 Q=1/0/−1로 변환한다. 타일 차이 숫자를 신경망 Q와 직접 비교하지 않는다.
- 승리하는 두 수가 각각 +1장과 +9장을 보장한다고 해서 +1장 승리를 실수로 분류하지 않는다. 이미 필패인 국면에서 타일 차이가 벌어지는 것 역시 ‘승리를 날린 큰 실수’로 분류하지 않는다.
- 현 탐색기의 타일 차이 최적화는 이 결과 우선순위와 양립한다. 다만 복기 등급은 타일 차이를 %p로 바꿔 계산하지 않는다.

## 5. 모든 수에 등급 부여

### 5.1 기본 등급 7단계

다음은 **초기 설계 경계값**이다. 현재 단계에서는 형세 평가 차이이며, 승률 보정 후에는 예상 승률 차이가 된다. 검증 결과로 조정하고 `gradingVersion`을 올린다.

| 등급 | 최선 대비 손실 | 표시 | 설명 |
|---|---:|---|---|
| 최선수 | 0 이상 1%p 이하 | ★ | 추천 수와 사실상 동급. 여러 수가 받을 수 있음 |
| 훌륭한 수 | 1%p 초과 ~ 3%p 이하 | !! | 최선에 매우 가까운 선택 |
| 좋은 수 | 3%p 초과 ~ 5%p 이하 | ! | 작은 차이로 형세를 유지 |
| 무난한 수 | 5%p 초과 ~ 10%p 이하 | ○ | 더 나은 대안이 있지만 손실은 제한적 |
| 부정확한 수 | 10%p 초과 ~ 20%p 이하 | ?! | 의미 있는 기회를 양보 |
| 실수 | 20%p 초과 ~ 35%p 이하 | ? | 형세를 크게 악화 |
| 큰 실수 | 35%p 초과 | ?? | 결정적인 손실 |

추가 규칙:

- 평가가 불안정하거나 경계값을 넘나들면 **판정 보류 / 추가 분석 중**이다. 빈 결과를 0 손실로 처리하지 않는다.
- 합법 수가 하나뿐이면 **강제수**, 그 수가 PASS면 **강제 패스**로 표시한다. 잘 고른 수나 실수의 통계에서 제외한다. `legal()`이 강제 패스를 반환하는 현재 규칙을 따른다.
- 정확 탐색이 완료되면 추정 등급보다 증명 결과를 우선한다. 결과를 유지하는 수는 동급 최선으로 처리한다.
- 정확한 승→패 전환은 큰 실수, 승→무 또는 무→패 전환은 실수로 분류하고 변화의 의미를 설명한다. 이미 패인 상태의 패→패는 타일 차이만으로 감점하지 않는다.
- 회전·대칭으로 같은 의미의 수와 오차 범위 내 동률을 하나의 정답으로 억지로 줄이지 않는다.

### 5.2 ‘놓친 수’는 상황 표시로 추가

‘놓쳤다’는 말은 손해의 크기 외에 **무슨 기회를 놓쳤는가**를 설명한다. 기본 등급과 함께 저장하고 `놓친 수 · 실수`처럼 보여준다. 그렇지 않으면 같은 수가 ‘실수’와 ‘놓친 수’ 중 어느 것인지 임의로 바뀐다.

| 상황 표시 | 조건과 설명 |
|---|---|
| 승리 기회를 놓침 | 정확 탐색에서 이기는 수가 있었으나 무승부/패배 수를 선택. 추정 분석에서는 최선 평가 ≥75%, 실제 수 ≤55%, 손실 ≥20%p이고 정밀 재검사에서도 유지될 때 ‘유리해질 기회를 놓침’으로 완화해서 표시 |
| 상대 실수를 살리지 못함 | 직전 상대 착수로 자신의 형세가 15%p 이상 개선되었으나, 위 기회 조건을 충족하는 대안을 두지 못함. 이전 평가는 모두 동일한 착수자 관점으로 환산 |
| 유일한 방어를 놓침 | 패배를 피하는 합법 수가 정확히 하나임이 증명됐고 다른 수를 선택. 추정만 있으면 ‘방어 기회를 놓친 것으로 추정’으로 표시 |
| 유일한 수를 찾음 | 유일한 승리 수 또는 유일한 패배 회피 수를 실제로 선택. 후보 전체를 검증했을 때만 ‘유일’이라고 표현 |
| 승리를 굳힘 | 증명된 승리를 유지하는 수. 원래 유리했다는 이유만으로 훌륭한 수를 남발하지 않음 |

‘묘수’나 ‘신의 한 수’는 1차 범위에서 제외한다. 낮은 정책 확률, 큰 뒤집기, 상대가 나중에 실수했다는 이유만으로 특별한 수를 만들지 않는다.

## 6. 승률·형세 그래프 재설계

- **정확한 위치:** 점 i는 i수가 끝난 보드 하나를 대표한다. 초기값도 분석한다. 서로 다른 국면의 이동평균을 기본값에서 제거한다.
- **일관된 시점:** +1 색 기준을 기본으로 고정하고 내 색 기준 전환을 제공한다. 축과 현재 숫자의 색 이름도 함께 바꾼다.
- **홀짝 문제 검증:** 차례별 잔차를 정확 후반 정답과 고예산 기준 평가에 대조한다. 평가가 홀짝으로 흔들리면 탐색·학습 데이터·보정을 개선한다. 부드러운 선만으로 원인이 해결됐다고 보지 않는다.
- **축과 수치:** Y축 0/25/50/75/100, X축 수 번호, 현재 값과 수 번호를 표시한다. 미분석 점은 선을 끊고 분석 중임을 보여준다. 0으로 채우지 않는다.
- **변곡점:** 큰 실수·실수·놓친 기회에 작은 기호를 찍고 선택하면 해당 착수 후 보드로 이동한다. 추천 수 버튼은 착수 전 보드로 이동한다.
- **모바일 조작:** 터치 드래그·탭으로 점 선택, 충분한 터치 영역, 슬라이더·키보드로 동일한 탐색을 제공한다. 색 외에 기호와 텍스트로 등급을 구분한다.
- **결과와 형세 분리:** 정상 종국만 규칙 엔진으로 마지막 평가를 확정한다. 기권·시간패는 당시 보드 평가를 유지하고 별도 결과 표시를 붙인다. 승자가 기록됐다는 이유로 마지막 보드 값을 100/0으로 덮어쓰지 않는다.
- **분석 근거:** ‘빠른 분석 / 정밀 분석 / 종국까지 확인’을 보여준다. 추정 99%와 증명된 승리를 같은 상태로 표현하지 않는다.

```text
AI 형세 평가 · 내 색 기준                  정밀 분석
100 ┤
 75 ┤       ╭────╮
 50 ┼───────╯    ╰─?────╮
 25 ┤                   ╰────
  0 ┤
    0       5      10      15        수 번호

12수 · 실수 · 유리해질 기회를 놓침
최선 대비 −24%p              [실제 수] [추천 수]
실제 수 평가 43 / 추천 수 평가 67
추천 수 → 상대 최선 응수 → 후속 수       [수순 보기]
```

예시는 화면 구조 설명용이며 실제 분석값이 아니다. 스킨·언어를 기존 설정과 연동하고 단색 면과 얇은 선이라는 앱의 디자인 원칙을 유지한다.

## 7. 복기 화면의 정보 구조

1. **대국 요약:** 두 색의 등급별 횟수, 평균 평가 손실, 결정적 기회 3곳. 강제수와 판정 보류는 집계에서 제외하고 분석 완료율을 같이 표시한다.
2. **현재 수 카드:** 수 번호·착수자·기본 등급·상황 표시·손실·평가 안정성.
3. **실제 수 / 추천 수 비교:** 회전한 타일과 놓는 위치를 함께 표시하고, 상대 응수까지 재생한다. 현재 보드 자동 중앙 정렬 뒤에도 착수 좌표가 맞는지 검증한다.
4. **전체 착수 목록:** 최선·좋은 수를 포함해 전부 제공한다. 내 수, 상대 수, 실수, 놓친 기회 필터와 이전/다음 주요 수 이동을 지원한다.
5. **설명:** ‘최선 수는 상대의 X 응수를 막습니다’ 같은 문구는 실제 수순과 규칙상 확인 가능한 사실에서만 만든다. 1차는 정형 설명으로 구현한다.

초기에는 불투명한 0~100 ‘정확도’ 점수를 도입하지 않는다. 평균 손실과 등급 분포를 먼저 제공한다. 나중에 점수를 도입하면 계산식·제외 항목·버전을 공개한다.

## 8. 데이터·워커·캐시 설계

화면 내부의 `analyzeGame()`을 독립 분석 모듈로 옮긴다. 단순 함수로 등급을 계산하고 UI는 저장된 분석 결과를 표시한다.

```ts
type AnalysisStatus = 'pending' | 'estimated' | 'stable' | 'exact' | 'error';

interface CandidateEvaluation {
  action: number;
  moverValue: number;        // −1..1, 비교 대상들은 같은 의미와 버전
  simulations: number;
  pv: number[];
  status: AnalysisStatus;
  exactOutcome?: -1 | 0 | 1;
  exactMargin?: number;     // 타일 차이, %p와 별도
}

interface MoveAnalysis {
  ply: number;              // 1부터, 부모 국면 인덱스는 ply−1
  player: 1 | -1;
  played: number;
  bestActions: number[];
  candidates: CandidateEvaluation[];
  lossPp: number | null;
  grade: string | null;
  badges: string[];
  forced: boolean;
  status: AnalysisStatus;
}
```

추가 저장 필드: 국면별 +1 색 평가와 상태, 기보 해시, 시작 국면·시작 차례, 규칙 버전, 모델 해시, 엔진 버전, 보정 버전, 등급 버전, 분석 모드, 실제 완료 예산, 오류·진행 상태. 기보를 재현할 때 합법성과 정상 종국 여부를 검사한다. 과거 기보에 시작 국면이 없으면 해당 규칙 버전의 초기판을 적용하고, 알 수 없는 규칙은 조용히 현재 규칙으로 분석하지 않는다.

- Worker 요청: `analyze`, `cancel`, `deepen`. 응답: `progress`, `position`, `move`, `complete`, `error`.
- 모든 요청에 `requestId`와 기보 식별자를 붙여 화면 이동·기보 변경 후 도착한 응답이 현재 결과를 덮어쓰지 못하게 한다.
- 분석 전용 워커 또는 명시적 작업 큐를 사용해 대국 AI와 경쟁하지 않게 한다. 동기 탐색과 긴 루프는 주기적으로 양보하고 취소를 확인한다. 메시지만 정의하고 실제 취소가 안 되는 상태로 끝내지 않는다.
- 진행률은 처리 완료 국면 수와 현재 단계로 표시한다. 먼저 나온 결과부터 그래프와 카드에 반영한다. 실패한 수만 재시도할 수 있게 한다.
- 원본 기보는 기존 저장소에 유지하고 큰 분석 자료는 IndexedDB에 저장한다. 캐시 키에 기보·시작판·차례·규칙·모델·엔진·보정·분석 설정을 포함한다. 등급만 바뀌면 원시 평가를 재사용해 다시 판정할 수 있다.
- 중단 시 완료한 수를 보관한다. 저장 공간 부족 시 오래된 분석 캐시부터 제거하고 기보와 사용자 전적은 유지한다. 100판 캐시 상한과 용량 상한은 실측으로 정한다.

## 9. 개선을 확인할 검증 기준

### 9.1 데이터 분할과 정답

- 기존 실전 원본 690판은 출발 자료로 사용할 수 있다. 퍼즐 후보와 출제 문제는 승리하는 착수 위주로 선택되어 있으므로 전체 착수 등급 검증을 대표하지 않는다.
- 원본의 패배 수, 강제 패스, 불리한 국면, 기권·시간패, 정상 종료, 짧은 기록과 무승부 경계 사례를 추가한다. 무승부가 드물면 별도 규칙 fixture로 처리한다.
- 같은 대국의 모든 국면과 회전·대칭·동일 수순 계열은 같은 분할에 넣는다. 대국 단위 60/20/20을 기본으로 하되 원본별 중복을 먼저 제거한다. 마지막 20%는 임계값 선택에 쓰지 않는다.
- 후반은 정확 탐색과 기존 독립 전수 검사기로 정답을 만든다. 초·중반은 고예산 기준 탐색을 사용하되 수학적 정답이라고 부르지 않는다. 별도 신규 대국으로 일반화도 확인한다.
- 기존/신규의 주요 실수 비교는 동일한 정답 정의를 사용한다. 예를 들어 고예산 기준 손실 20%p 이상을 공통 사건으로 고정하고, 정확 후반의 승패 전환은 별도 집계한다. 신규 등급의 이름이나 자체 임계값을 정답으로 쓰지 않는다. 오탐 감소와 함께 기존 대비 재현율 유지도 요구한다.
- 확률 보정용 자료는 선택된 퍼즐이 아니라 고정 정책으로 이어 둔 완료 대국에서 만든다. 동일 대국 내 상관을 고려해 대국 단위로 오차와 불확실성을 계산한다.

### 9.2 제안하는 출시 기준

아래 수치는 달성했다고 주장하는 결과가 아니라 구현 후 평가할 **합격 목표**다. 첫 벤치마크에서 자료량과 기기 조건을 확정한다.

| 항목 | 목표 |
|---|---|
| 규칙·관점·그래프 위치 | 색 변환, 차례 변환, i수↔S_i 매핑, 강제 패스, 승·무·패 fixture 전부 통과 |
| 정확 탐색 표시 | ‘종국까지 확인’으로 표시한 모든 수가 독립 검사와 일치. 예산 초과를 exact로 표시하는 사례 0 |
| 후반 착수 판단 | 정답이 있는 후보에서 승패를 잘못 분류한 비율이 기존 대비 감소. exact 완료 부분의 승패 분류 오류 0 |
| 주요 실수 탐지 | 확정 승→패와 유일 방어 누락의 정밀도·재현율을 각각 보고. exact 완료 구간에서는 누락 0 |
| 초·중반 개선 | 고예산 기준 대비 최선 수 집합 일치율·순위 후회값을 함께 비교. 주요 실수 오탐률 기존 대비 30% 이상 감소를 목표로 설정 |
| 등급 안정성 | 예산 2배 증가 시 이미 stable로 표시한 수의 95% 이상에서 기본 등급 유지. 경계 수는 보류 비율도 함께 공개 |
| 평가 오차 | 고예산/정확 기준 대비 MAE와 차례별 잔차를 보고. 그래프 곡선의 매끄러움만으로 품질을 판정하지 않음 |
| 승률 명칭 도입 | 대국 단위 검증에서 Brier score 개선과 보정 곡선을 확인. 충분한 표본이 있는 구간에서 ECE 5%p 이하를 목표로 하되 ECE 하나만으로 승인하지 않음 |
| 초기 반응 | 모델 로딩 후 첫 부분 결과 2초 이내를 목표. 모델 다운로드·워밍업 시간은 별도 보고 |
| 일반 분석 시간 | 23수 안팎 기보의 p95 목표: 지정 PC 15초, 지정 중급 Android 45초. 기기·모델·예산과 함께 실측하고 미달 시 범위를 조정 |
| 취소 | 취소 500ms 이내 반응을 목표. 취소 뒤 진행 응답·완료 응답이 다른 기보를 덮어쓰는 사례 0 |
| 재열기·오류 | 동일 버전 캐시 재사용, 부분 재개, 모델 로딩 실패·저장 실패·기보 변경·화면 이탈 시나리오 통과 |

보류를 늘려 정확도만 높이는 편법을 막기 위해 분석 완료율, stable 비율, exact 완료율, 보류 비율을 품질 지표와 함께 공개한다. 결정적 실수 표본이 적으면 비율만 제시하지 않고 실제 건수와 대국 단위 신뢰구간을 함께 보고한다.

확률 보정은 확률과 실제 빈도의 일치를 따로 확인해야 한다. [Guo 등, On Calibration of Modern Neural Networks, ICML 2017](https://proceedings.mlr.press/v70/guo17a.html)을 검증 설계의 참고로 사용한다. 단일 회귀 value에 분류용 temperature scaling을 그대로 적용하지 않고, 출력 의미에 맞는 단조 보정 또는 WDL 보정을 검증한다. 기대 결과를 예측하는 value와 탐색의 구분은 [AlphaZero 원 논문](https://www.davidsilver.uk/wp-content/uploads/2020/03/alphazero-science_compressed.pdf)도 참고한다.

| 3. 사용성 | 부분 결과, 취소, 오류 복구, 캐시·재개, 모바일 조작 | 긴 분석·화면 이탈·재열기 검증 | 1~2일 |
| 4. 출시 검증 | 보류 경계 조정, 고정 평가셋 검사, 모바일 예산 조정 | 품질·완료율·성능 보고서, 일반 분석 배포 가능 판정 | 1~2일 |
| 5. 실제 승률 | WDL 학습·내보내기, 고정 정책 대국 수집, 보정·별도 검증 | 검증 통과한 예상 승률과 무승부 표시 | 자료·학습 시간 측정 후 별도 산정 |

1인 개발 기준 1차 형세 분석 개선은 약 7~11 작업일의 가정이다. 기존 그래프 증상과 기기 성능에 따라 재산정한다. 실제 승률 모델 학습은 이 일정에 포함하지 않는다.

**1차 완료 조건:** 모든 착수에 등급 또는 명시적인 보류·강제수 상태가 있고, 그래프의 점이 보드와 정확히 대응하며, 추천 수에 상대 응수 근거가 있고, 후반 증명 상태를 구분한다. 같은 고정 기보에서 기존보다 실수 판정이 개선됐다는 보고서를 남겨야 한다.

**가장 먼저 착수할 변경:** 그래프를 단독 수정하기 전에 `SearchResult` 확장과 독립 분석 모듈을 만든다. 그 결과를 수 등급과 그래프가 함께 사용하게 해야 화면과 분석 근거가 일관된다.
