# 수 평가 기준 변경 구현·검증

2026-11-16. [변경 계획](move-grading-intuitiveness-plan.md)의 기본 등급, 설명 화면, 보조 표시, 신뢰도, 캐시 전환, 검증 도구를 구현했다. 웹·PWA·서버 빌드를 완료했다.

## 변경한 동작

- 추정 등급은 최선 대비 AI 평가점 손실로만 정한다. 경계는 1·3·5·10·20·35점이며, `! 좋은 수`는 3점 초과~5점이다. 착수 전 평가보다 좋아지는 유일한 수라는 이유로 `★`를 `!`로 덮어쓰지 않는다.
- 분석 모듈이 기본 등급, 잠정 등급, 판정 이유, 손실, 후보 비교값, 보조 표시, 근거 상태를 함께 생성한다. 화면은 이 결과를 읽으며 등급을 다시 계산하지 않는다.
- 모든 추정 등급에 관측된 탐색 변동과 등급 경계 검사를 적용한다. 기존에 예외였던 최선수와 좋은 수도 경계를 넘나들면 잠정으로 남긴다. 이 변동은 통계적 신뢰구간이 아니다.
- 정확 탐색은 승·무·패 결과로 판정한다. 승리 유지와 최선의 저항, 승→무, 무→패, 승→패에 서로 다른 설명을 붙인다. 같은 결과를 유지하는 후보는 타일 차이와 관계없이 동급 최선이다.
- 유일한 승리 수와 유일한 방어는 기본 등급 옆에 별도로 표시한다. 같은 결과 판을 만드는 행동 번호들은 하나의 선택지로 세며, 기준 도움말에 이 원칙을 설명한다. 추정만으로 유일성을 단정하는 표시는 도입하지 않았다.
- 선택한 수 카드에 등급, 근거 상태, 한 문장 이유, 실제 수·추천 수의 평가를 표시한다. 추정은 평가점, 종국 증명은 승·무·패로 보여준다. 실제 수와 추천 수를 전환해 응수를 재생할 수 있고, 후속 수순이 부족하면 해당 수만 추가 분석한다.
- 추가 분석을 취소하거나 다른 기보로 이동하면 이전 응답이 화면을 덮어쓰지 않는다. 추가 분석 중 다른 수를 선택해도 완료 응답이 선택 위치를 되돌리지 않는다.
- 강제수·강제 패스는 등급과 통계에서 제외한다. 잠정 실수는 목록과 그래프에서 `~`로 구별하고 확정 집계에 포함하지 않는다. 평균 손실은 안정된 추정 수만 대상으로 하며, 종국 승패의 인위적인 50점·100점 차이를 평균에 섞지 않는다.
- 범례에서 7단계 이름·손실 구간·의미를 확인할 수 있다. 한국어·영어·일본어·중국어를 지원한다.

## 캐시와 호환성

`GRADING_VERSION`은 3, 수 분석의 `ANALYSIS_VERSION`은 5로 갱신했다. 이전 등급 캐시는 새 키와 구분해 다시 분석한다. 새 캐시는 저장된 후보와 공통 판정 결과가 일치하는지 확인하며, 이유·등급·손실·상태가 모순되면 거부한다.

승률 그래프의 버전 3과 캐시 키는 유지했다. Chrome 검사에서 수 등급 캐시만 삭제한 뒤 다시 열어 그래프 데이터가 그대로 재사용되는 것을 확인했다. `lossPp`는 기존 호출자 호환 필드로 남기고, 새 코드와 화면에서는 `lossPoints`를 사용한다. 값의 의미는 미보정 AI 평가점이다.

## 자동 검사

- 최초 전체 검사: 162개 중 161개 통과, 기존 온라인 봇 대국 테스트 1개가 60초 제한 초과. 서버 테스트 파일을 재실행해 **24개 모두 통과**했다. 테스트 제한이나 서버 동작을 변경하지 않았다.
- 최종 관련 검사: **50개 모두 통과**. 등급 경계와 부동소수점 오차, 단조성, 기본 등급 덮어쓰기 방지, 최선수·좋은 수 경계 보류, 공동 최선, 강제 패스, 보조 표시, 종국 결과 설명, 표시 일치, 캐시 일관성, 번역을 포함한다.

## 실제 Chrome 검사

격리한 프로필에서 실제 ONNX 워커와 프로덕션 빌드를 검사했다. 사용자 기보나 브라우저 프로필을 사용하지 않았다.

- 390×900 모바일 폭과 1440×1000 PC 화면, 320px 폭의 4개 언어에서 카드와 펼친 기준 설명의 가로 넘침이 없었다.
- 카드·보드·착수 미리보기·목록·그래프에서 등급과 잠정 표시가 일치했다. 밝은/어두운 테마의 7색과 SVG 아이콘 위치를 확인했다.
- 범례의 터치 조작과 실제 Enter 입력, 실제 수·추천 수·상대 응수 재생, 그래프 포인터·키보드 조작을 검사했다.

- 증명 예산이 부족한 경우에는 잠정 이유와 평가점이 표시되는 것을 허용하며, 모든 자식이 종국인 별도 국면에서 확정된 승패 이유와 비교값을 검사했다.
- 최종 실행의 런타임 오류는 0건이었다. 23수 기보 전체 표시와 취소 조작의 시간은 아래 검사 보고서에 기록했다. 준비된 자산 캐시를 사용하는 단일 실행이며 p95·최초 다운로드·Android 성능으로 해석하지 않는다.

## 기보 비교 결과와 해석

[비교 보고서](../tools/analysis/grading-v3/report.json)는 원본 기보에서 고른 **30판·667수**를 포함한다. 강제수 5수를 제외한 평가 대상은 662수다. 대칭·색 반전으로 같은 전체 수순은 묶어서 대국 단위로 분할했고, 세부 검사에는 기준 조정용 대국과 같은 국면을 제외했다. 임계값은 이 결과로 재조정하지 않았다.

같은 후보 평가값에 기존 표시 규칙과 새 표시 규칙을 적용한 결과다. 정확 탐색 시간 예산은 이 빠른 비교 경로에서만 0으로 고정했다.

| 등급 | 기존 표시 | 새 표시 |
|---|---:|---:|
| 최선수 | 244 | 246 |
| 훌륭한 수 | 55 | 55 |
| 좋은 수 | 2 | 51 |
| 무난한 수 | 156 | 105 |
| 부정확한 수 | 88 | 88 |
| 실수 | 60 | 60 |
| 큰 실수 | 57 | 57 |

최선인데 특수 조건으로 좋은 수로 표시되던 **2수**를 바로잡았다. 좋은 수 구간을 추가해 기존 무난한 수 51수가 좋은 수로 구분된다. 이 표는 등급 정의의 일관성 비교이며, 실수 탐지 정확도가 개선됐다는 증거로 사용하지 않는다.

별도 12국면에서 후보 탐색의 기본 예산 12→24→96을 비교했다. 종국 증명을 제외한 고예산 결과는 탐색 비교 기준이며 수학적 정답으로 보장하지 않는다.

- 후반 4국면은 모두 종국까지 확인했고 결과와 등급을 유지했다.
- 초·중반 8국면은 낮은 예산에서 모두 잠정이었다. 예산을 두 배로 늘렸을 때 표시 등급을 유지한 수는 4/8이었다. 높은 예산에서는 이 중 2수가 안정된 최선수로 판정됐다.
- 따라서 이 표본으로 **안정된 추정 등급의 95% 유지율을 검증할 수 없다.** 종국 증명 4수를 안정성 분모에 섞어 100%를 주장하지 않는다.
- 이 12개의 실제 착수에는 고예산 기준 20점 초과의 주요 실수 사례가 없었다. 초·중반의 주요 실수 정밀도·재현율, 기존 대비 오탐 감소도 이 표본으로 입증하지 않았다.

빠른 등급 경로의 Node/WASM 측정은 중앙값 23.772초, p95 41.149초였다. 준비된 모델과 대국별 빈 추론 캐시 조건이며 다른 검사도 병행한 PC 측정이다. 이전 엔진 전체와의 속도 개선 비율이나 모바일 성능으로 해석하지 않는다. 기존 방식의 추가 부모 평가 비용은 보고서에 별도로 기록했다.

```powershell
npm run bench:grading -- 30 12
# 별도 터미널에서 127.0.0.1:5181 프로덕션 미리보기 서버 실행 후
node --import tsx tools/check_analysis_ui.ts
```

앱 기능 구현과 자동·브라우저 검증은 완료했다. 초·중반 안정성 95% 목표와 주요 실수 탐지 성능은 대표 표본 확대가 필요하다. 실제 Android 기기 지연과 사용자가 설명을 얼마나 이해하는지에 대한 관찰도 후속 검증으로 남긴다.
