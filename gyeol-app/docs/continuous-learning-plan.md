# 대국이 쌓일수록 좋아지는 분석 신경망 계획

2026-11-20. **목표는 정밀 분석이 지금 하는 일을 신경망이 미리 배워 두게 하는 것이다.** 대국과 복기가 늘어날수록 학습 데이터가 자동으로 쌓이고, 주기적으로 새 모델을 학습·검사한다. 검사를 통과한 모델만 배포 후보로 올린다.

**결정(2026-11-20):** 수집·라벨·학습·관문은 Oracle 서버(A1 Flex, ARM64)에서 돌린다. 데이터는 서버 DB에 남는 온라인 대국(사람끼리, 사람 대 서버 AI 봇)과 자가대국만 쓴다. 기기에만 남는 AI 대국과 둘이서 두기는 쓰지 않는다. 배포는 매번 보고서를 보고 승인한다. 코드는 `github.com/ybs1164/gyeol`(공개)에서 관리한다.

## 1. 지금 상태와 문제

| 항목 | 현재 | 근거 |
|---|---|---|
| 모델 | `900c6f08b6ce0aba` 1개(2026-10-21 내보냄). 대국 AI·복기 그래프·수 등급·봇이 모두 같은 파일을 쓴다 | `apps/web/public/model`, `analysis-version.ts` |
| 학습 데이터 | 자가대국만 사용. 마지막 학습은 2026-10-24 | `gyeol_ai/facing/temp` |

신경망 하나의 판단이 약하다. 그래서 많은 탐색(정밀 분석)과 후반 정확 증명으로 부족한 부분을 메우고 있다. 지금 정밀 분석이 계산하는 결과를 학습 정답으로 다시 쓰면, 다음 모델은 같은 판단을 적은 탐색으로 할 수 있다(증류).

## 2. 원칙

1. **자동으로 학습하고, 배포는 관문을 통과한 것을 사람이 승인.** 모델을 바꾸면 봇 레이팅, 승률 보정, 타일 차이 계수(`MARGIN_PER_VALUE`), 저장된 분석 캐시가 함께 바뀐다. 자동 배포는 하지 않는다.
2. **사람 대국의 승패를 정답으로 쓰지 않는다.** 사람은 실수하므로 승패는 국면의 가치를 뜻하지 않는다. 사람 대국에서는 *실제로 나오는 국면*만 가져오고, 정답은 서버가 정확 탐색과 깊은 탐색으로 다시 계산한다(재분석).
3. **정답은 서버에서만 만든다.** 서버가 직접 진행한 대국의 수순만 쓰고, 기기가 계산한 분석값은 쓰지 않는다.
4. **시험 세트는 얼린다.** 학습에 절대 쓰지 않는 고정 시험 국면으로만 모델을 비교한다. 데이터가 늘어도 비교 기준은 바뀌지 않는다.
5. **식별자 없는 학습 파일.** 학습 데이터에는 닉네임·계정 ID·기기 정보 없이 수순·규칙·시작 국면·사람/봇 구분만 남긴다. 학습 파일은 서버 밖으로 내보내지 않고 저장소에도 넣지 않는다.

## 3. 데이터 흐름

```
[온라인 대국 DB] ─┐
(사람·봇 대국)    ├─▶ ① 수집·중복 제거 ─▶ ② 재분석 라벨 ─▶ ③ 학습 ─▶ ④ 자동 관문 ─▶ ⑤ 배포 후보·보고서 ─▶ (승인) ─▶ 배포
[자가대국]        ─┘                                                       └─ 실패: 기록만 남기고 현 모델 유지
```

### ① 수집

- 서버: 끝난 대국(`status='finished'`)의 수순을 매일 JSONL로 내보낸다. 기존 `db-cli`에 `export-training` 명령을 추가한다. 내보낸 위치(커서)를 기록해 같은 대국을 두 번 내보내지 않는다.
- 규칙 재생으로 합법성을 다시 검사하고, 맞지 않는 수순은 버린다. 봇끼리 둔 대국은 없지만(봇은 항상 사람과 둔다), 봇 쪽 수도 국면 분포로는 쓸 수 있다.
- 국면 단위로 펼친 뒤 8가지 대칭을 정규형으로 합친 해시로 중복을 제거한다. 시작 국면 근처는 모든 대국이 같으므로 국면마다 표본 수 상한을 둔다.
- 기권·시간패로 끝난 대국도 국면은 쓸 수 있다(정답을 다시 계산하므로). 2수 이하 대국은 버린다.

### ② 재분석 라벨

남은 타일 수에 따라 정답의 질이 다르다.

| 남은 타일 | 가치 정답 | 정책 정답 | 타일 차이 정답 |
|---|---|---|---|
| ≤ 10 (증명 가능 범위) | `ExactEndgame` 정확 승패 | 정확 탐색의 최선수 집합 | 정확 최종 차이 |
| 그 외 | 현재 최고 모델의 깊은 탐색(예: 800회) 루트 값 | 루트 방문 분포 | 같은 판에서 깊은 탐색끼리 둔 끝의 차이(선택) |

- 라벨러는 Node로 만든다. 앱과 같은 `packages/core` 규칙, `ExactEndgame`, `search`, 서버의 `brain.ts`(onnxruntime) 경로를 그대로 쓴다. 규칙 구현이 Python과 어긋날 위험이 없다. 출력은 Python 학습이 읽는 JSONL(보드, 차례, 정책, 가치, 차이, 라벨 종류, 라벨을 만든 모델 버전)이다.
- 라벨을 만든 모델이 바뀌면 오래된 탐색 라벨은 점차 다시 계산한다(재분석). 정확 라벨은 모델과 무관하므로 영구히 쓴다.
- 이것이 "정밀 분석을 미리 배우는" 핵심이다. 기기에서 15분 걸리는 계산을 서버가 한가할 때 한 번 하고, 그 결과를 모든 사용자의 다음 모델에 넣는다.

### ③ 학습

- 현재 `best.pth.tar`에서 이어서 미세 조정한다. 처음부터 다시 학습하지 않는다.
- 섞는 비율: 재분석한 사람 국면 50%, 자가대국 50%로 시작한다. 사람 국면만 쓰면 자주 나오는 수에만 맞춰지고 다른 국면을 잊는다.
- **타일 차이 출력(margin head) 추가.** 가치·정책 옆에 최종 타일 차이를 예측하는 출력을 붙인다. 정답이 있는 표본(정확 라벨, 자가대국 종국)만으로 학습한다. 이 출력이 생기면 `MARGIN_PER_VALUE = 8.27` 근사를 대체한다. 지금 근사의 평균 오차가 4.6장이다.
- 과신 줄이기: 정확 라벨이 있는 후반 국면의 가치 손실 가중치를 높인다. 학습이 끝나면 승률 보정 계수를 새 모델 기준으로 자동으로 다시 맞춘다(`fitProbability`, 기존 파일럿과 같은 분할 규칙).
- ONNX 출력 형태가 바뀌므로(차이 출력 추가) `createPredictor`와 `Prediction` 타입은 차이 값이 없어도 동작하게 먼저 확장한다.

### ④ 자동 관문

모두 통과해야 배포 후보가 된다. 기준은 첫 실행 전에 고정하고, 결과를 보고 바꾸지 않는다.

| 검사 | 데이터 | 통과 기준(초안) |
|---|---|---|
| 정확 국면 가치 | 얼린 시험 세트(정확 라벨 5,000국면, 학습 제외) | 승패 적중률·Brier가 현 모델보다 좋음 |
| 정밀 분석 대체 | `standard-vs-deep`의 8판 + 새로 얼린 사람 대국 20판 | **새 모델의 빠른 분석이 현 모델의 정밀 분석과 최선수 일치율 ≥ 현재보다 +10%p**, 정확도 차이 감소 |
| 대국 강도 | 다양한 시작 국면, 선후공 교환 | 현 모델 상대로 순차 검정(SPRT)으로 우위 확인. 지금 `arenaCompare: 40`판은 너무 적다 |
| 타일 차이 | 시험 세트 | 평균 오차 < 4.6장(현재 근사) |
| 안전 | ONNX 변환 | 기존 `publish_facing_model.py` 검사(추론 오차, 출력 범위) 통과. 추론 시간 증가 ≤ 20%, 파일 크기 ≤ 3MB |

### ⑤ 배포 후보와 보고서

관문을 통과하면 다음을 자동으로 만든다. 배포는 승인 후에 한다.

- `model.onnx`, `model-info.json`, 새 `MODEL_VERSION`
- 새 모델 기준 승률 보정 계수, `MARGIN_PER_VALUE`(차이 출력이 없을 때만), 봇 레이팅 재보정(`calibrate_bots.ts`)
- 보고서: 관문 표, 사용한 데이터 수(사람/자가대국/정확 라벨), 지난 모델과의 비교 그래프

배포 후:

- `MODEL_VERSION`이 바뀌면 저장된 분석이 다시 계산된다. 예전 결과는 지우지 말고 "이전 모델 분석"으로 남긴다. 새 분석이 끝나면 교체한다.
- 이전 모델 파일 3개를 보관해 즉시 되돌릴 수 있게 한다.

## 4. 언제 돌리나

- 수집·라벨: 매일 밤(서버 또는 이 PC). 새 국면이 없으면 건너뛴다.
- 학습: 새로 라벨한 국면이 2만 개 이상 쌓였거나, 지난 학습 후 2주가 지났을 때. 이 PC 기준 한 번에 약 5시간(CPU)이다.
- 대국 수가 적은 초기에는 자가대국과 재분석 비율이 학습을 끌고 간다. 사람 국면은 "실제로 나오는 국면을 더 정확히" 하는 보정 역할이다. 사람 대국이 늘수록 이 효과가 커진다.

## 5. 위험과 대응

| 위험 | 대응 |
|---|---|
| 사람 대국이 적거나 소수의 플레이어에게 쏠림 | 플레이어별 표본 상한, 자가대국 50% 유지 |
| 새 모델이 예전 국면을 잊음 | 얼린 시험 세트 + 대국 강도 관문 |
| 일부러 이상하게 둔 대국 | 승패를 정답으로 쓰지 않으므로 정답은 오염되지 않는다. 플레이어별 표본 상한으로 국면 분포 쏠림만 막는다 |
| 모델 교체로 봇 레이팅·순위가 흔들림 | 봇 재보정 후 배포. 레이팅 정책 버전을 함께 올린다 |
| 계산 비용(깊은 탐색 라벨) | 정확 라벨(후반)부터 채우고, 깊은 탐색은 하루 예산 안에서만. 남은 시간이 많은 국면은 정밀 분석과 결과가 크게 다른 국면을 먼저 처리한다 |
| 개인정보 | 학습 파일에 식별자 없음, 서버 밖 반출 금지, 저장소에 넣지 않음 |
| 게임 서버 성능 저하 | 학습은 별도 systemd 서비스로 `Nice=19`, `CPUQuota`, `MemoryMax`를 두고 게임 서비스(메모리 2GB 한도)와 분리한다. 진행 중 대국이 있으면 깊은 탐색 라벨은 쉬어 간다 |

## 6. 실행 순서

| 단계 | 산출물 | 끝났다는 기준 |
|---|---|---|
| P0 기준선 | 얼린 시험 세트(정확 라벨), "빠른 분석 vs 정밀 분석" 지표 스크립트, 현 모델 점수 | 같은 명령으로 같은 숫자가 다시 나옴 |

| P2 라벨러 | Node 재분석 라벨러(정확 → 깊은 탐색 순) | 표본 1,000국면의 정확 라벨이 `ExactEndgame` 직접 계산과 일치 |
| P3 학습 확장 | Python 학습에 외부 라벨 JSONL 혼합, 타일 차이 출력, ONNX·예측기 호환 | 확장된 모델이 기존 앱에서 그대로 동작 |

| P5 주기 실행 | Oracle systemd 타이머(수집→라벨→학습→관문), 승인 후 배포 스크립트 | 사람 개입 없이 후보와 보고서가 생성됨 |

P0~P2는 지금 데이터로 바로 할 수 있다. P3부터 Python 학습 코드를 건드린다.

## 7. P0 기준선 결과 (2026-11-21)

시험 세트 `exact-test-v1`: 2026-11 봇 대국에서 뽑은 2,377국면(남은 타일 4~9장, 구간당 약 400). 정확 승패 정답, 4~7장은 정확 타일 차이까지. 노드 한도로 23국면(1%)이 빠졌다(9장에서 19개). 만드는 데 7프로세스로 28분 걸렸다. 도구와 사용법은 [`tools/learning`](../tools/learning/README.md).

현재 모델(`model.onnx` sha `9ec913ce7828de12`, 학습 체크포인트 `900c6f08`) 채점(64회 탐색, 이 PC 9분):

| | 승패 적중 | Brier (0.25 = 항상 50%) | log loss | 보정 오차(ECE) | 타일 차이 평균 오차(0으로 찍으면 7.39) |
|---|---|---|---|---|---|
| 신경망 단독 | 62.8% | **0.302** | 1.264 | 0.280 | 7.13 |
| 64회 탐색(그래프와 같은 방식) | 79.5% | 0.137 | 0.426 | 0.046 | 4.29 |

- **신경망 단독은 항상 50%라고 말하는 것보다 확률 오차가 크다.** 98%라고 말한 국면(852개)의 실제 초록 승리는 68%, 2%라고 말한 국면(836개)은 30%였다. 남은 타일이 많을수록 나빠져 9장에서는 적중률 57%다.
- 64회 탐색이 이 과신을 대부분 지운다. 지금 복기가 탐색과 정확 증명에 기대는 이유가 이것이다.
- 이 국면들은 정확 탐색으로 정답을 싸게 만들 수 있는 범위다. ②의 정확 라벨로 학습하면 바로 줄일 수 있는 오차다.
- 첫 관문 목표(초안): 신경망 단독 Brier < 0.25, 적중률 ≥ 70%. 64회 탐색 지표는 현재보다 나빠지지 않음.

## 11. P3 학습 확장 결과 (2026-11-21)

- 신경망에 타일 차이 출력(`m_fc1`·`m_fc2`, tanh × 25장)을 더했다. 예전 체크포인트는 이 출력만 비어 있는 채로 불러오고(`load_compatible`), 다른 키가 빠지면 실패한다. ONNX 출력은 `log_policy`·`value`·`margin`(장 단위). 앱 예측기는 `margin`이 있으면 읽고 없으면 무시하므로 지금 모델도 그대로 동작한다.
- `gyeol_ai/train_distill.py`: 라벨 JSONL과 기존 자가대국 리플레이를 반반 섞어 미세 조정한다. 라벨 읽을 때 Python 대칭 키를 다시 계산해 TS 키와 다르면 멈추고, 얼린 시험 세트 국면은 뺀다. 결과는 `candidate.pth.tar`와 `report.json`.
- 시험 학습: 봇 대국에서 뽑은 국면 34,057개(정확 29,954 · 증명 1,503 · 탐색 2,600, 200회 탐색)로 3,000걸음, 이 PC 8스레드 25분.
  - 따로 떼어 둔 라벨에서 정확 승패 적중 83.6% → 88.5%, 타일 차이 평균 오차 8.0 → 2.76장.
  - 리플레이 검증 value MSE는 0.467 → 0.486으로 조금 나빠졌다(자가대국 분포를 약간 잊음).
  - **주의:** 이 시험 학습의 기준 체크포인트 `facing/temp/best.pth.tar`(`0b4f3d05`)는 배포 모델이 아니었다. 배포 모델(`model.onnx` `9ec913ce`)의 체크포인트는 `facing/temp/candidate_895dca1012de_2.pth.tar`(`900c6f08`, 출력이 배포 ONNX와 완전히 같음)이고, `best.pth.tar`는 그 뒤(10-24) 학습만 하고 배포하지 않은 모델이다. 서버에는 `900c6f08`을 넣었고 `cycle.sh`가 매 회차 이를 확인한다.
