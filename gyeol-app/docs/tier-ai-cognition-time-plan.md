# 티어별 AI의 판단 시간·가중치 적용 지연 설계안

작성일: 2026-11-14. 현재 소스를 조사한 수정 계획이며, 아래 시간·계수는 구현 후 조정할 실험 초깃값이다. 사람의 실제 사고 시간을 측정한 결과가 아니다. 이번 작업에서는 실행 코드와 운영 레이팅을 변경하지 않는다.

## 1. 권장 방향

AI의 실력을 **판단 요소를 얼마나 빨리 알아차리는가, 제한 시간 안에 얼마나 검토하는가**로 나눈다. 착수는 그 시점까지 인식·검토한 결과 중 최고 점수의 합법 수를 결정적으로 선택한다.

- 낮은 티어: 즉시 뒤집는 장수에 먼저 반응하고, 상대 반격과 장기 손익을 늦게 반영한다. 충분히 생각하기 전에 현재 판단으로 착수할 수 있다.
- 높은 티어: 상대 반격을 일찍 반영하고, 애매한 후보에 검토 시간을 집중한다. 쉬운 수는 빠르게, 중요한 선택은 오래 검토한다.
- 시간 부족: 검토 범위와 깊이가 줄어 실수가 발생한다. 별도의 실수 추첨은 사용하지 않는다.
- 같은 AI·국면·시간 조건·엔진 버전이면 같은 수를 선택한다. 후보 동점도 고정 순서로 해소한다.

여기서 가중치는 **평가 요소의 반영 계수**를 뜻한다. ONNX 신경망의 학습 파라미터를 시간에 따라 바꾸거나, 모델 로딩을 일부러 늦추는 설계가 아니다. 현재 모델은 policy와 value를 한 번에 내므로, 그 출력을 즉시 사용하면서 상대 반격만 늦게 깨닫게 만들 수는 없다. 학습 모델을 사용하는 단계 자체를 분리한다.

## 3. 시간에 따라 판단이 깊어지는 구조

한 수를 다음 네 단계로 구성한다. 각 단계의 인식 시작 시간과 처리 속도를 개인별로 고정한다.

| 단계 | 판단 내용 | 구현 근거 |
|---|---|---|
| A. 즉시 이득 | 이번 수의 타일 차이 변화, 뒤집는 장수 | `apply()`, `margin()`, `MoveInfo.flipped` |
| B. 상대 반격 | 상대가 바로 되가져갈 수 있는 이득, 내 다음 합법 수 변화 | 후보 적용 후 상대 응수를 실제 생성·적용 |
| C. 짧은 수읽기 | 반격 뒤 내 응수까지의 손익, 연속 패스·종국 | 고정 평가 함수를 쓰는 제한 깊이 탐색. 결과 관점은 루트 착수자 기준 |
| D. 학습 판단 | 학습 모델의 후보 선호와 깊은 탐색 가치 | 고정 모델의 MCTS. policy는 탐색 우선순위, Q는 후보 평가로 구분 |

결 규칙은 타일 방향과 회전에 좌우되므로 오델로의 모서리 점수 같은 규칙을 그대로 가져오지 않는다. 특히 보드가 매 수 중앙 정렬되므로 화면의 절대 좌표에 보너스를 주지 않는다.

초기에는 합법 수마다 A 점수를 계산한다. 이후 현재 드러난 점수순으로 후보를 검토하며, 시간이 생기면 다음 후보를 추가한다. B·C·D의 새 결과는 정해진 검토 단위를 완료했을 때만 공개한다. 아직 검토하지 않은 값을 0점이나 안전하다는 근거로 취급하지 않는다.

```text
g_k(t) = clamp((t - start_k) / ramp_k, 0, 1)
S(a,t) = Σ [baseWeight_k × g_k(t) × F_k(a)] / Σ [baseWeight_k × g_k(t)]
```

- `t`는 해당 수에서 실제로 진행한 사고 시간이다. 가중치가 열렸어도 해당 후보의 계산이 끝나지 않았다면 평가에 사용할 수 없다.
- `F_k`는 공통 범위 −1..1로 정규화한 루트 착수자 기준 점수다. 장수 차이와 MCTS Q를 원래 단위 그대로 더하지 않는다. 정규화·기본 계수도 버전 관리한다.
- 후보 비교는 같은 단계까지 완료한 집합끼리 한다. 검토가 끝난 유망 후보가 있으면 그 집합에서 선택하고, 하나도 없으면 직전 단계의 순위를 사용한다. 검토 집합 밖의 좋은 수를 놓치는 현상은 후보 확장으로 완화한다.
- A는 즉시 사용하고, B·C·D의 반영을 순차적으로 연다. 짧은 배치마다 계수를 갱신해 매 순간 모든 후보를 다시 계산하는 비용을 줄인다.
- 확인한 실제 종국 결과는 휴리스틱 점수보다 우선한다. 미완료 탐색을 종국 증명으로 취급하지 않는다.

**중요한 구현 경계:** 시간마다 달라지는 계수를 MCTS의 leaf value에 직접 넣으면 기존 트리의 Q와 새 평가가 섞인다. 첫 버전에서는 A~D의 결과를 루트 밖의 판단 계층에서 결합하고, MCTS 내부 모델·평가·prior는 세션 동안 고정한다. 세션은 보드·모델·검색 설정이 같을 때만 재사용한다. D가 열리기 전에는 모델 policy로 후보를 정렬하지 않는다.

## 4. 티어별 초기 프로필

다음은 **3분 모드·여유 있는 시계** 기준이다. 시간은 봇 차례가 시작된 뒤 각 요소의 반영을 시작할 수 있는 가장 이른 시각이다. 이후 가중치는 각 요소의 시작 시간의 50%에 해당하는 구간 동안 선형으로 증가한다. 실제 완료 시각은 계산량에도 좌우된다.

| 설계 목표 티어 | B 반격 인식 | C 짧은 수읽기 | D 학습 판단 | 우선 검토 후보 수 | 일반적인 착수 목표 |
|---|---:|---:|---:|---:|---:|
| 브론즈 | 2.4초 | 5.5초 | 9.0초 | 2 | 1.2~3.5초 |
| 실버 | 1.6초 | 3.8초 | 6.5초 | 3 | 1.0~3.5초 |
| 골드 | 1.0초 | 2.3초 | 4.0초 | 4 | 0.9~3.5초 |
| 플래티넘 | 0.65초 | 1.5초 | 2.8초 | 6 | 0.8~3.5초 |
| 다이아몬드 | 0.40초 | 0.95초 | 1.7초 | 8 | 0.7~3.5초 |
| 마스터 | 0.25초 | 0.55초 | 1.0초 | 12 | 0.6~3.5초 |

착수 목표는 강제 대기 범위가 아니다. 쉬운 수는 더 빨리 둘 수 있고, 복잡한 수는 시계가 허용하면 더 오래 생각한다. 예를 들어 브론즈가 1.8초에 착수하면 반격을 아직 반영하지 못하지만, 4초 동안 검토했다면 반격을 일부 반영할 수 있다. 다이아몬드도 촉박한 시계에서는 D를 충분히 반영하지 못한다.

초기 후보 수는 검토의 시작 폭이며 이후 시간에 따라 확장한다. 인식 시간이 열려도 후보 전부의 상대 응수를 무제한 전수 검사하지 않는다. 응수·노드 단위의 고정 작업량을 배정하고 미완료 상태를 기록한다.

1분에서는 인식 시간·검토 단위당 사고 시간을 0.65배, 5분에서는 1.15배로 시작해 모드별 실력을 재측정한다. 짧은 모드에서도 각 티어가 실제로 어떤 판단 단계까지 도달하는지 확인한다. 1일 모드는 남은 24시간을 총 대국 시계처럼 나누지 않고, 일반 착수 상한 8초·복잡한 국면 상한 15초부터 실험한다.

낮은 티어가 시간을 더 쓰면 무조건 마스터처럼 되지 않도록 동일 시간에서의 검토 속도·후보 확장 속도도 다르게 둔다. 반대로 높은 티어라고 모든 수를 오래 기다리게 하지 않는다.

## 5. 인간답게 시간을 배분하는 규칙

목표 행동은 사람이 두는 느낌을 위한 설계 가설로 두고, 실제 사용자의 체감과 대국 로그로 확인한다.

| 현재 관찰한 상황 | 시간 사용 |
|---|---|
| 합법 수가 하나 | 최소 조작 시간 후 착수. 강제 PASS는 기존 서버 자동 패스 흐름 유지 |
| 검토한 후보 중 1위가 명확하고 추천이 안정됨 | 티어가 요구하는 최소 확인을 마쳤다면 일찍 착수 |
| 상위 후보 점수가 비슷함 | 다음 후보·상대 응수 검토에 추가 시간 배정 |
| 반격 검토 후 추천 수가 바뀜 | 바뀐 후보를 한 번 더 검토하고 착수 시간 연장 |
| 검토 중 큰 손실이나 종국 분기가 발견됨 | 남은 시계 안에서 해당 분기를 우선 검토 |
| 시계 부족 | 깊은 단계의 새 작업을 중단하고 마지막 완료된 판단으로 착수 |

복잡도는 처음부터 최강 AI가 분석해 알려주지 않는다. 초기에는 합법 수 수와 A 점수 격차만 사용하고, 이후 본인이 실제 검토한 반격·추천 변경·미검토 후보 수로 갱신한다. 아직 공개되지 않은 D의 평가로 시간이나 조기 착수를 결정하면 인식 지연이 무효가 된다.

상위 티어의 최소 확인은 적어도 주요 후보의 반격 검토를 포함한다. 하위 티어는 A 단계에서도 충분한 점수 격차가 있으면 착수할 수 있다. 안정성은 완료한 검토 배치 사이의 추천 유지로 계산하고, 점수만 같은 미검토 상태를 안정적이라고 부르지 않는다.

3분·5분·1분 모드의 시간 예산은 아래에서 시작한다.

```text
left = 서버가 계산한 현재 잔여 시간
reserve = min(left × 0.25, max(250ms, 측정한 추론·스케줄링 지연 여유))
safe = max(0, left - reserve)
r = 남은 배치 타일 수에서 추정한 내 남은 착수 수, 최소 1
base = safe / (r + 1)
target = min(safe, modeCap, base × 관찰된 복잡도 배수)
```

- 남은 배치 수는 `TOTAL_TILES - tileCount(board)`로 계산하고 패스가 있는 경우 추정을 보정한다. 한 판 평균 길이를 고정 상수로 쓰지 않는다.
- 조기 착수는 목표 시간 전에 가능하다. 연장도 하드 마감을 넘지 않으며, 1차 상한은 1분 4초·3분 10초·5분 15초부터 검증한다.
- 시간이 거의 없으면 최소 대기 시간보다 마감을 우선하고 이미 계산한 합법 수를 즉시 제출한다. 합법 수 기본 후보는 모델 호출 전에 확보한다.
- **목표 대기 시간과 계산 마감을 함께 제한한다.** 현재 코드처럼 대기만 줄이고 탐색은 계속 돌지 않도록 한다.

## 6. 실행 구조와 서버 부하

개인별 프로필은 `startTimes`, `rampTimes`, `candidateLimit`, `workRate`, `earlyCommitGap`, `minimumChecks`를 갖는다. 1,000명은 이 연속 파라미터를 보간해 생성하며, 매 수 약한 기준 AI와 강한 기준 AI를 추첨하지 않는다. 일부 파라미터만 다른데 실제 행동은 같은 경우도 생기므로, 1,000명 각각의 실력이 고유하다고 사전 보장하지 않는다.

행동 프로필의 `skillPosition`은 생성 시 고정하고 실측 레이팅은 별도 저장한다. 재보정 점수에서 티어를 다시 구해 행동이 자동으로 바뀌는 순환을 피한다. 위 표의 티어는 목표 구간이며, 보정 후 표시 티어가 다르면 프로필을 조정하고 다시 검증한다.

실행은 `초기 후보 확보 → 다음 판단 작업 예약 → 완료 결과 공개 → 착수/연장 판정`을 반복한다.

- 실제 연산 속도와 설계한 인식 속도를 분리한다. 고정 노드/추론 작업량마다 최소 사고 시간을 부여해, 빠른 PC나 캐시 적중만으로 낮은 티어가 더 많은 판단을 얻지 않게 한다.
- 미리 계산된 결과는 공개 시점까지 판단·시간 배분에서 사용할 수 없다. 실제 계산이 늦으면 완료되지 않은 결과를 공개하지 않는다.
- 계산을 동시 실행하더라도 서버의 시계는 계속 흐른다. 대기열 시간은 추가 판단으로 환산하지 않으며, 과부하로 인한 품질 저하는 별도 지표로 기록한다.
- 현재 `getBrain()`은 모든 추론을 직렬화한다. 깊은 봇 하나가 독점하지 않도록 작은 작업 배치와 대국별 공정한 순서를 둔다. 추론 대기열에 들어간 작업도 마감을 재확인한다.
- 마감은 시뮬레이션 시작 전과 추론 전후에 확인한다. 단일 ONNX 호출은 즉시 취소가 안 될 수 있으므로 메인 대국 스케줄러는 미리 확보한 수로 마감 착수할 수 있어야 한다. 이벤트 루프를 막는 계산은 작업자로 옮긴다.
- 취소·마감 후 늦게 온 계산은 버린다. 기권·종국·서버 종료 시 예약 작업을 정리한다. 착수 직전 `gameId`, `ply`, 봇 차례와 대국 상태를 재확인한다.
- 서버 재시작 때 `turnStartedAt` 이후의 경과 시간은 잔여 시계에서 반영하되, 꺼져 있던 동안 읽었다고 취급하지 않는다. 판단을 다시 구성하며 마감이 가까우면 기본 후보를 사용한다.

성격 차이는 즉시 이득을 중시하는 정도나 검토 순서처럼 고정 파라미터로 추가할 수 있다. 첫 버전에서는 실력·시간 정책을 먼저 검증한다. 매칭 상대를 고르는 무작위성은 착수 판단과 별도이며 이번 교체 범위에서 유지한다.

## 8. 검증과 레이팅 전환

현재 레이팅은 기존 확률적 행동으로 측정한 값이다. 새 엔진에 그대로 붙이지 않는다. 현재 보정기는 시계 없이 `personaMove()`를 반복하므로 새 시간 기반 실력을 검증할 수 없고, `--fit-only`로 기존 원자료를 재계산하는 것만으로도 해결되지 않는다.

필수 검증은 다음과 같다.

1. **선택 재현:** 가상 시계·고정 작업량에서 동일 국면과 프로필은 같은 결과. 시간별 점수·도달 단계·착수 이유를 기록한다.
2. **인식 지연:** B·C·D의 공개 전 결과를 바꿔도 그 이전 착수와 시간 배분이 변하지 않는다. 캐시 유무에도 논리 사고 예산은 같다.
3. **시간의 효과:** 같은 국면에 0.5/1/2/4/8초를 주고 인식 단계·검토 후보·선택 손실 변화를 비교한다. 개별 국면에서 탐색 증가가 항상 개선된다고 가정하지 않고 평가셋 전체로 판단한다.
4. **티어별 차이:** 눈앞의 큰 이득이 반격당하는 국면, 유일한 방어, 후보가 비슷한 국면, 강제수, 패스, 종국을 포함한다. 하위 티어의 실수가 실제로 늦은 인식·검토 누락에서 발생했는지 로그로 설명할 수 있어야 한다.
5. **마감·취소:** 모델 초기 로딩, 느린 추론, 동시 대국, 잔여 시간 극소, 기권·재시작·종료 후 늦은 응답을 검사한다. 불법 수와 끝난 대국의 추가 착수는 0건이어야 한다.
6. **실제 시계 대국:** 1분·3분·5분을 각각 새 원자료로 측정한다. 1일 모드도 별도 예산으로 확인한다. 선후공과 시작 국면을 교차하고 기존 확률 엔진·고정 강한 기준 엔진과도 비교한다.
7. **시간 사용 품질:** 쉬운/복잡한 국면의 시간 분포, 시계 잔여량별 사용 시간, 추천 변경 뒤 추가 검토, 단계별 도달률, 시간패와 서버 지연을 보고한다. 사람이 느끼는 자연스러움은 블라인드 플레이 비교로 별도 확인한다.

논리 시계로 기다림을 생략한 보정과 실제 ONNX·실제 마감 대국을 구분한다. 보정 입력에는 모델 해시·행동 버전·모드·시작 국면·노드 예산·실행 환경을 넣고, 기존 `roster-v2` 원자료는 보존한다.

처음에는 각 목표 티어의 대표 6~12개 프로필로 검증한다. 인접 실력 구간의 순서와 선후공 영향을 확인한 뒤 1,000명으로 늘린다. 미세 파라미터 보간이 레이팅의 선형 증가를 보장하지 않으므로 새 결과로 순서와 보간 근거를 다시 만든다.

현재는 하나의 레이팅을 표시하므로, 첫 전환에서는 3분 모드를 기준으로 삼고 다른 모드에서 실력 순서가 유지되는지 확인한다. 차이가 크면 시간 파라미터를 조정하거나 모드별 레이팅 도입을 별도 결정한다. 검증 전에는 현재 랭크전에 새 행동을 붙이지 않고 실험 대국에서 비교한다.

## 9. 구현 순서와 완료 조건

| 순서 | 작업 | 완료 조건 |
|---|---|---|
| 1 | A·B 판단과 가상 시계, 결정적 후보 선택 | 반격 인식 전후에 선택이 달라지는 재현 가능한 예시 확보 |
| 2 | 티어별 지연·램프·조기 착수, C·D 연결 | 같은 시간에서도 티어별 도달 단계와 검토량이 다름을 로그로 확인 |
| 3 | 서버 시계·공정한 큐·하드 마감·취소 | 계산이 늦어도 기본 후보로 마감 대응하고 대국 상태를 안전하게 유지 |
| 4 | 대표 프로필 대전·수치 조정 | 실력 구간 순서, 손실, 시간 사용, 시간패·부하 보고서 확보 |
| 5 | 1,000명 생성·재보정·버전 전환 | ID·이름·기존 전적 보존, 새 레이팅 근거와 되돌리기 자료 확보 |
| 6 | 오프라인 4난이도 적용 | 공통 엔진 사용, 되돌리기·재시작·화면 이탈 시 작업 취소 검증 |

첫 구현 목표는 **브론즈가 당장의 큰 이득을 보고 먼저 착수하고, 다이아몬드는 같은 시간 안에 반격을 인식해 다른 수를 고르는 것**이다. 두 선택의 차이가 난수 없이 판단 과정과 시간으로 설명되어야 한다.
